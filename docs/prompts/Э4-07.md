# Э4-07: атлас — источник узлов симуляции

Автор: Fable, 16.11

**Исполнитель:** ведущий (Opus) + конвейер (К1 → `@sim-worker`)
**Цель:** симуляция строится из JSON атласа любой локации без правки кода: строковые id, размеры массивов по числу узлов; добавление локации в Э5 — это новый файл атласа, а не новый сценарий на Java (г1, г6, решение б).

## Прочитать
- `b-atlas.md` (схема, б3, б4), `review-fable-2.md` раздел 2 «б)» (правило б-П5: малые аванпосты, укрытия, сектора, зоны потенциала — не узлы), г-П12, раздел 4 «Объём данных атласа»; `sim/KordonScenario.java`, `ZoneScenario.java`, `Scenarios.java`, `Simulation.java` (`knowledge = new double[64]`), `People.java` (`zombies = new double[64]`), результат Э2-05 (Кордон из атласа), `atlas.schema.json`.

## Шаги
1. Карточка К1 (`NodeCountTest`): сценарий из 300 узлов живёт 30 дней без `ArrayIndexOutOfBounds`; все массивы «на 64» получают размер `nodes.size()`. Поиск остальных жёстких размеров — `grep` по `64` и `MAX_NODES` в `sim/`.
2. `sim/AtlasScenario`: читает файлы локаций атласа → узлы (базы, крупные аванпосты и блокпосты, поля, логова, переходы), рёбра, группы-владельцы, сектора и укрытия (данные, не узлы), зоны потенциала, стартовые запасы. Обобщить то, что Э2-05 сделала для Кордона; второй путь чтения не заводить.
3. Таблица «строковый id ↔ индекс» — одна на симуляцию; индекс наружу (`ZoneData`, сеть, сохранение) не выходит.
4. `KordonScenario` остаётся для тестов, пока `AtlasKordonTest` не покажет совпадение набора узлов и стартовых чисел; затем помечается устаревшим (не удалять — на нём 78 тестов).
5. Проверки при загрузке: связность базы со складом и входом в Зону, уникальность id, владелец — существующая группа; ошибка — понятное сообщение и отказ от загрузки локации, а не падение сервера.
6. `atlas/original/*.json` (≈ 650 КБ, нужны только инструментам) мод при старте не разбирает; перенести из ресурсов jar в `tools/`.
7. Точки секторов хранить массивами координат; разбор всего атласа при старте ≤ 300 мс (замер в `AtlasTest`), иначе — локации по первому обращению.
8. Локации без файла атласа симуляции не получают (пусто, «нет данных») — до Э5.

## Разрешённые файлы
Новый `sim/AtlasScenario.java`, `sim/Scenarios.java`, `sim/Simulation.java`, `sim/People.java`, `sim/Node.java`, код чтения атласа из Э1-13/Э2-05, `src/main/resources/data/stalkerzone/atlas/*` (перенос `original/`), `tools/*`, тесты, `docs/tasks/*`, `tools/ci/test_sources.sh`.

## Проверка и приёмка
К1, `AtlasKordonTest`, `AtlasTest` зелёные; синтетический атлас 400 узлов загружается и живёт 30 дней; jar меньше на размер `atlas/original`. Смена набора узлов Кордона здесь не допускается (иначе сброс истории) — только источник данных.

## Видно в игре
Только данные: Кордон в игре тот же, что до задачи (сверка `/zone people` и числа узлов до и после). Заметно станет в Э5, когда локации появляются файлами.
