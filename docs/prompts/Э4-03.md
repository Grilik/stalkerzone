# Э4-03: `ServerSystem` и одно состояние сервера; `/zone perf`

Автор: Fable, 16.11

**Исполнитель:** ведущий (Opus)
**Цель:** 19 статических вызовов `X.tick(server)` в `StalkerZoneMod.onServerTick` заменены одним списком систем с замером времени; всё состояние сервера живёт в одном объекте, который создаётся при старте мира и уничтожается при остановке (г1, г8; `04-target-architecture.md`, строка `world.systems`).

## Прочитать
- `StalkerZoneMod.java` (`onServerTick`, события старта и остановки сервера), `ServerWatchdog.java`, `ZoneData.java`, менеджеры `npc/*Manager`, `world/*Manager`, `anomaly/*`, `pda/ZoneLifeService`; `agent-team-audit/04-target-architecture.md`, `05-problems-and-risks.md` (статика между мирами).

## Шаги
1. Интерфейс `ServerSystem { String name(); int cadence(); void tick(MinecraftServer s); }` и один упорядоченный список в `StalkerZoneMod`. **Порядок и частоты — ровно как сейчас** (включая ветку `% 40` и вызовы вне основного условия); порядок закреплён тестом-списком имён.
2. Обёртка замера: на систему — среднее, максимум и 99-й перцентиль за последние 1 200 тиков; сторож (`ServerWatchdog`) при долгом тике называет систему.
3. `/zone perf`: таблица по системам и по фазам суточного шага (Э4-01), TPS, число сущностей мода.
4. Одно состояние сервера: объект `ZoneServer` (или `ZoneData` как корень) держит всё, что сейчас в `static`-полях менеджеров; создаётся в `ServerStarting`, обнуляется в `ServerStopped`. Перенос — по одному менеджеру на коммит.
5. Тест-сканер `NoServerStaticsTest` (по исходникам): в перечисленных пакетах нет изменяемых `static`-полей, кроме белого списка с объяснением.
6. Клиентские синглтоны (`ClientPda`, `PdaModel`) — сброс при выходе из мира.

## Разрешённые файлы
`StalkerZoneMod.java`, `ServerWatchdog.java`, `ZoneCommands.java`, `ZoneData.java`, новые `ServerSystem.java`, `ZoneServer.java`, менеджеры из списка тика (только перенос состояния и подключение), `client/ClientPda.java`, тесты, `tools/ci/test_sources.sh`.

## Проверка и приёмка
Тест порядка систем и сканер зелёные; дымовой сервер зелёный; **два мира подряд в одном запуске клиента** (кнопка «Зона» дважды): во втором нет NPC, отрядов и меток первого; `/zone perf` показывает все системы; накладные расходы замера ≤ 0,05 мс/тик.

## Видно в игре
Команда `/zone perf` — таблица времени по системам; сообщение сторожа с именем системы.

## Чек-лист для игры
- Создать мир, поиграть 5 минут, выйти в меню, создать второй — чужих данных нет.
- `/zone perf` — нет системы дольше 8 мс в среднем.
