## Рецепт локации (общий для Э5-03…Э5-20)
1. **Разведка** (`@scout`): съёмка Э1-04 локации, `atlas/original/<файл>.json` (только подсказка, какие места должны быть), `docs/thezone/places.json`, строка локации в `09-container-loot.md`. Итог — список построек TheZone-кандидатов с координатами.
2. **Места по F3.** Пользователь даёт 5–15 точек (ворота баз, переходы, приметные здания); остальное — подобием с подгонкой к рельефу (ошибка пересчёта 30–50 блоков). Локации 1:1 с оригинала не копируем.
3. **Превью ролей** — карта локации с подписями: базы, малые базы, крупные и малые аванпосты, поля, логова, укрытия, переходы, зоны потенциала. Пользователь утверждает **весь набор узлов локации одним заходом**.
4. **Атлас** `data/stalkerzone/atlas/locations/<id>.json`: базы (`area`, `gates`, `buildings`, `sectors`, точки NPC — инструмент Э1-14), аванпосты по правилам Э1-15 (крупные — узлы с укрытием, малые — с `parent`, не узлы), зоны потенциала Э1-16 (без еды и воды), поля, логова, переходы `exit`, дороги. Id — строки, после слияния не переименовываются.
5. **Группы и стартовый состав** — в атласе локации: группа-владелец каждой базы и крупного аванпоста, число людей, склад, касса. Стартовые запасы — «начальное» в `Ledger`, не `created`. Еда — только привозной запас.
6. **Укрепления и заборы** — инструментом Э2-01 в рабочей копии мира, журнал с откатом, превью «до/после» пользователю. Постройки TheZone не сносить и не перестраивать.
7. **Проверки**: валидатор атласа; `Atlas<Локация>Test` (связность баз со складами и переходами, укрытие у каждого крупного аванпоста, вместимость укрытий ≥ стартового гарнизона, владелец у каждого узла); `ZoneBenchTest` и `audit()` на 365 дней × 6 сидов с новой локацией.
8. **Сохранение.** Локация добавляется новыми записями секций кодека Э4-05; существующие id и история не сбрасываются (тест К32: сохранение без локации загружается с локацией, прежние узлы — с прежним состоянием).
9. **Мир.** Контейнеры уже разложены Э1-17 по бюджету локации — не пополнять. Одна пересборка золотой копии на локацию; обновить `TheZone-trial`; лог: `chunkWrites=0`, `substitutions=0`, сторож молчит.
10. **Плейтест** пользователя 20–30 минут по чек-листу задачи.

## Общие правила (для всех промптов Э5–Э8)
- Действуют «Общие правила» `docs/prompts/Э3-Э4-plan.md` (а через них — `Э2-01.md`): одна задача — одна ветка — один PR с номером в заголовке; мир и данные GSC в git не класть; блоки при загрузке чанка не писать; подпись коммитов.
- **Сохранение.** После Э4-05 новые данные — новая секция кодека с версией; незнакомая секция пропускается, отсутствующая заполняется из атласа; ссылки — строковые id (узел, сектор, группа, `PersonId`). Смена набора узлов уже слитой локации — только с миграцией. Каждое изменение формата — эталонное сохранение в `src/test/resources/saves/`.
- **Деньги и вещи физичны.** Ничего не возникает и не исчезает; таймеров уничтожения нет; `destroyed` — только расход; запись в `Ledger` вне `sim/` запрещена (тест-сканер Э4-04).
- **Цены** — только `economy/Prices` и `prices.json`.
- **Группы.** Владелец узла, склада, кассы, отряда — группа; фракция выводится.
- **Еда и вода** — только привозные; мясо мутантов — радиация и риск болезни.
- **Выброс** не отнимает точки; у каждого гарнизона есть укрытие.
- **Знания.** После Э7-06 мозг группы видит только `IntelView`; сервер шлёт игроку только то, что он знает (Э3-08).
- **Производительность.** Суточный шаг ≤ 15 мс (медиана, `ZoneBenchTest`), уровень А ≤ 8 мс/тик, сохранение ≤ 2 МБ; малые аванпосты, укрытия и зоны — не узлы.
- **Тесты** — `main()` в `src/test/java/ru/stalkerzone/…`, каждый — в `tools/ci/test_sources.sh`; карточки — `docs/tasks/` с полем «Видно в игре».
- **Экраны** — набросок картинкой в PR до кода.
