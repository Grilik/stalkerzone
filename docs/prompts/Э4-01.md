# Э4-01: логова, аномалии, маршруты — отдельные подсистемы `Simulation`; фазы суточного шага

Автор: Fable, 16.11

**Исполнитель:** конвейер (карточки → `@sim-worker`), строго по одной: общий `Simulation.java`
**Цель:** `Simulation.java` (≈ 3 000 строк) перестаёт быть единственным местом логики: логова, аномалии и маршруты вынесены в свои классы под свои тесты; суточный шаг разбит на именованные фазы с планировщиком (г1, г8). Поведение не меняется.

## Прочитать
- `g-simulation-whole-zone.md` г1 («Бюджет тика», варианты исполнения шага), г8; `docs/claude/agent-team-audit/04-target-architecture.md`; `sim/Simulation.java` (`step()`), `Lair.java`, `LairTerritory.java`, `Anomaly.java`, `AnomalyDistrict.java`, `ZoneGraph.java`, `Crossings.java`; `SimDeterminismTest`.

## Шаги
1. **Эталон до правок:** тест `StepGoldenTest` — байты сохранения после 90 дней `kordon` и `zone` на 3 сидах, снятые с текущего `main`. Каждая карточка обязана оставить их равными.
2. Карточка 1: `sim/LairSystem` — всё о логовах и набегах (набег остаётся как есть; перенос «15 % склада в `destroyed`» на поле узла — Э8-04, не здесь).
3. Карточка 2: `sim/AnomalySystem` — поля, артефакты, выброс (после Э2-18: точки не отнимает, укрытия).
4. Карточка 3: `sim/Routes` — обёртка над `ZoneGraph`, закрытие дорог, переходы; единственная точка, через которую остальной код спрашивает путь (нужна для Э4-10).
5. Карточка 4: фазы шага. Перечисление `StepPhase` (население, экономика, логистика, политика, война, мутанты, аномалии, аудит) — **не путать с существующим `sim/Phase`** (фаза группировки). `step()` = проход по фазам; планировщик умеет «все фазы в одном тике» (по умолчанию, как сейчас) и «по фазе за тик» (выключен, включится по результату Э4-09). Замер времени каждой фазы.
6. Подсистема получает `Simulation` только через узкий интерфейс (узлы, группы, `Ledger`, ГСЧ); порядок обращений к ГСЧ не менять — иначе эталон разойдётся.
