# Э8-10: `Ledger` всей Зоны — счета и книги населения и мутантов

Автор: Fable, 16.11

**Исполнитель:** `@sim-worker` по карточкам К3, К16; ведущий — счета на границе с миром
**Цель:** закон сохранения на всю Зону — три книги, которые `audit()` сводит каждый день: товары и деньги, население, мутанты. Новая строка карты (в решении г) ошибочно названа Э8-08).

## Прочитать
- Решение г) г3 «Закон сохранения на всю Зону» с поправкой г-П6; карточки К3, К12, К16; ревизия, раздел 4 «Сохранения» п. 5; `sim/Ledger.java` (`worldLoot` — есть с v23), `sim/Stock.java`, `sim/Lair.java`, `sim/PersonRegistry.java`, `sim/WorldGateway.java`, `container/WorldLoot.java`.

## Шаги
1. Книга 1, новые счета: **«у игроков»** — граница системы (взял игрок — вывоз, отдал или продал — ввоз; инвентарь игрока симуляция не ведёт); **«на руках»** — сумма инвентарей записей людей; **«в аренде»** — инвентарь людей уровня А до отчёта `release`; **«в мире»** (`worldLoot`) — добыча контейнеров (остаток бюджета локации), рюкзаки, груз на точке; **эскроу** заданий (Э8-05).
2. Инвариант: Σ(склады групп, рынки и склады узлов, грузы караванов, на руках, в аренде, в мире, эскроу) = начальное + created + imported + отданное игроками − destroyed − exported − взятое игроками. `destroyed` — только расход.
3. Контейнеры: бюджет локации выдан заранее и записан; наполнение лениво из тика, детерминировано от `simSeed` и позиции; сумма не зависит от порядка открытия (тест: два порядка — одна сумма). Повторного наполнения из воздуха нет.
4. Книга 2 (К3): Σ записей людей по состояниям = начальное + пришло по каналам − ушло − умерло; переходы между группами сумму не меняют; зомбированные — отдельный счёт.
5. Книга 3 (К16): Σ(логова + бродячие) = начальное + родилось + пришло − погибло; без добычи логово не растёт; мясо и части — из погибших мутантов.
6. `audit()` раз в игровой день; расхождение — запись в лог с разбивкой по счетам и сторож (как сейчас), в тестах — падение. Команда `/zone audit` — три книги.
7. Запрет записи `Ledger` вне `sim/` — тест-сканер Э4-04; проверить, что новые счета пишутся только через шлюз.
8. Цена проверки: `audit()` на 450 узлах, 1 200 людях ≤ 2 мс.

## Проверка и приёмка
К3, К16 зелёные; 365 дней × 10 сидов — три книги сходятся каждый день; сервер в CI: бот торгует, убивает, открывает контейнеры 3 игровых дня — `/zone audit` без расхождений; тест порядка открытия контейнеров зелёный.

## Видно в игре
Напрямую — только `/zone audit`. Косвенно: ничего не дублируется и не пропадает — вынесенное игроком из Зоны делает её беднее.

## Чек-лист для игры
- `/zone audit` после часа игры с торговлей и боем — расхождений нет.
- Открыть контейнеры одного здания в разном порядке в двух копиях мира с одним сидом — содержимое одинаково.
