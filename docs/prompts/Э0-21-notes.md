## База — огороженная территория с зданиями и секторами (пользователь, 18:01–18:10)
Источник: мастер-проект 10.11, §17 и приложение I §9 (`Faction → Group → Base → Building → Sector → Upgrade Level`; сектора: штаб, казармы, склад, мастерская, медпункт, оборона, энергетика, жильё, торговля, производство, лаборатория, разведка, гараж; «не каждая база имеет всё»; паспорт базы и сектора).

**Как понимать базу.** Пример — НИИ Агропром: это не одно здание, а **территория за забором** с несколькими зданиями. В главном корпусе может быть несколько секторов, остальные — в других зданиях территории. Нельзя, чтобы все рабочие места оказались в одном здании, а остальные пустовали.

**Задача Э1-14 — механизм границ базы и раскладка секторов** (в схеме атласа Э1-13 зданий и секторов нет):
1. **Граница базы.** Инструмент по съёмке Э1-04 (растр и список построек) находит территорию: замкнутый забор/стена с воротами (заливка области, ограниченной оградой), а если ограды нет — по плотности построек и дорог (выпуклая оболочка с отступом). Результат — многоугольник `area` базы, ворота (`gates`), здания внутри. Пользователь утверждает границу на превью (как контур Зоны), правки — вручную в атласе.
2. **Здания базы.** Для каждого здания внутри: контур, этажи (по высоте и перекрытиям), входы (двери, проёмы), лестницы, полезная площадь, тип по форме (корпус, ангар, барак, вышка, бункер, сарай).
3. **Раскладка секторов.** Набор секторов берётся из роли базы (доктрина группировки, размер базы). Правила: каждое пригодное здание получает хотя бы одну функцию; крупное здание — несколько секторов по этажам/крыльям; сектор подбирается к зданию по типу и площади (склад и гараж — ангар; казарма — барак или этаж корпуса; штаб и разведка — главный корпус; оборона — вышки, ворота, периметр; медпункт — ближе к центру); у сектора есть вход с территории. Итог — предложение раскладки на превью, утверждает пользователь, правки — вручную.
4. **Места NPC.** Внутри секторов и на территории — рабочие места, места отдыха и сна, посты охраны и патрульные маршруты по периметру, костёр/общее место; плотность — по вместимости сектора; места не в стенах и проходимы (проверка навигацией).
5. **Схема атласа:** у объекта-базы `area`, `gates`, `buildings[]`; у здания — `outline`, `floors`, `entrances`, `sectors[]`; у сектора — id, назначение, объём (коробки по этажам), входы, `points`, статус. Валидатор: здания внутри `area`, сектора одного здания не пересекаются, точки внутри своего сектора, у сектора есть путь до ворот. `points` объекта остаются для лагерей без зданий.

Живые базы Э2-15/Э6-05 опираются на эту раскладку: рабочее место NPC = точка сектора; сектор без людей или разрушенный — его функция не работает. Уровни секторов (Э5-14) отложены, но объём сектора — уже то место, которое позже будет меняться улучшением. Первый образец — базы Кордона (деревня новичков, блокпост, АТП, элеватор), затем эталонная промышленная база (Э5-02, Агропром).

**Потенциал территорий вместо мини-баз (Э1-16).** Мини-базы (элеватор, руины дома на Кордоне) заменяются оценкой того, что зона может дать. Базы условно двух видов: **основные крупные** базы группировок и **базы поменьше с локальной задачей** (занятая зона с производством, постом, складом). Для каждой зоны атласа — набор потенциалов с силой:
- **еды и воды зона не даёт** (уточнение 19:14); лес — дерево/стройматериалы; металлолом, техника, свалки — детали;
- аномальное поле — артефакты (после выбросов); логово — части и мясо мутантов;
- заводской корпус, гараж — мастерская или производство; склад — хранение;
- развилка дорог и переход — торговля, пошлина; подвал/бункер — укрытие от выброса.
Группировка, оценив зону (разведка, угрозы, логистика, люди — как экспансия Э7-04), занимает её и делает требуемое: доп. производство, пост, склад, укрытие. Пока стройка отложена (Э5-13) — только **существующие постройки TheZone** (в них сектор с функцией по потенциалу); новые постройки — когда вернётся стройка. Производство идёт из реальных ресурсов зоны через `Ledger`, ресурс зоны не бесконечный (восстанавливается с задержкой). Источник потенциала — съёмка Э1-04 (материалы блоков, вода, лес, постройки) + разметка оригинала Э1-05.

Одиночки — несколько автономных групп (деревня новичков, ферма, охотники/проводники…), объединяются, делятся, меняют лидеров. Бандиты — конкурирующие банды (АТП, дальний блокпост…): притоны и лагеря, плата за проход, грабёж караванов, распад после гибели главаря. `FactionRelations` + `GroupRelations`; параметры группы (агрессия, тяга к расширению, дисциплина, сплочённость, осторожность, мораль, влияние лидера). Переход человека — явное событие. Сохранение — с версией (Э0-14a).
- **Аванпосты (Э1-15, на Кордоне Э2-07).** По оригиналу + свои доработки. **Крупные значимые** — мосты, тоннели, переезды, переходы, подходы к базам: укрепления (мешки, бетонные блоки, вышка, пулемётное гнездо) и укрытие (здание, подвал, блиндаж). **Малые** — укрепления на дорогах и у аномалий. На Кордоне крупные: мост, тоннель под насыпью, южный и дальний блокпосты. Укрепления ставит инструмент Э2-01 до раздачи мира (стройка в рантайме по-прежнему отложена).
- **Выброс (Э2-18, затем Э9-07).** Точки **остаются** за группировками, которые их удерживают. Сейчас `Simulation.emission()` отдаёт слабо охраняемые точки (`n.owner = -1`, Э0-17 сделала исключение только для одиночек Кордона) — убрать для всех. Отряды по предупреждению идут в ближайшее **укрытие** — целые здания, подвалы, убежища (`shelter` в атласе: у здания/сектора — флаг и вместимость); кто не успел — гибнет или ранен; после выброса — возврат на точки. В мире NPC реально бегут в укрытие (`EmissionEvent.nearestShelter` уже есть — расширить на здания атласа).
