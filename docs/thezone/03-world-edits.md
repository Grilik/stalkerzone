## Как править
Мир должен быть **закрыт** (игра, сервер). Все команды — из `tools/thezone`, Python 3.11+:

```
python -I world_edit_log.py setblock C:/MineStalker/TheZone-work X Y Z minecraft:stone --why "зачем"
python -I world_edit_log.py log    C:/MineStalker/TheZone-work     # список правок
python -I world_edit_log.py verify C:/MineStalker/TheZone-work     # файлы совпадают с журналом
python -I world_edit_log.py undo   C:/MineStalker/TheZone-work e0007
```

Большие правки (чистка Э1-10, декор Э1-12, постановки Э2-01 до раздачи) — из своего скрипта через тот же журнал:
```python
from world_edit_log import Work
w = Work("C:/MineStalker/TheZone-work")
eid = w.begin("что", "зачем", ["region/r.-9.6.mca", ...])   # резерв этих файлов + md5 «до»
...правка через anvil.read_chunk / set_block / write_chunk...
w.commit(eid)                                               # md5 «после»; при ошибке — w.undo(eid)
```

Правила инструмента:
- Работает только в папке с меткой `WORKCOPY` — оригинал и `The Zone` править откажется.
- Перед записью копирует затронутые файлы в `backup\` и проверяет копию по md5.
- Одна открытая правка за раз.
- **Откат** `undo <id>` возвращает файлы из резерва и проверяет md5 «до». Отказ — если те же файлы потом меняла другая правка (сначала откатить её) или если файл изменён мимо журнала (например, мир открывали в игре).
- Журнал только дописывается: откат — новая строка, история не теряется.

## Что пишет журнал
Строка на событие (`init`, `begin`, `commit`, `undo`): `id`, что, зачем, координаты, файлы, путь резерва, md5 до и после, git sha инструмента, время.

## Если что-то пошло не так
- `verify` показал расхождение — мир меняли мимо журнала (открывали в игре — Minecraft пересохраняет чанки). Либо записать это правкой, либо вернуть файлы последним `undo`.
- Рабочая копия испорчена целиком — удалить её **только с согласия пользователя** и скопировать заново из `08_BACKUPS\TheZone-original\world` (затем `init`).
