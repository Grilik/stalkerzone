# Э1-16: потенциал территорий вместо мини-баз

Решения: `docs/claude/decisions/b-atlas.md` (б1 «Потенциал зоны», б3 «зоны не узлы», б4 валидатор),
`docs/claude/decisions/g-simulation-whole-zone.md` (г4 «Занятие зоны»), `docs/prompts/Э0-21-notes.md`
(пользователь, 15.11 18:42 и 19:14), `docs/roadmap.md` (блок решений 15.11). Карточка — `docs/project-tasks.json`, Э1-16.

Мини-базы (элеватор, руины дома) заменены оценкой того, что территория может дать. Группировка занимает
территорию и ставит там локальную задачу по её потенциалу. **Еды и воды территория не даёт.**
Стройка отложена (Э5-13): занятие идёт в **существующих постройках TheZone**, новые объекты не создаются,
блоки не пишутся, базой территория автоматически не становится.

## Территория в атласе

Объект `kind: zone` (схема `data/stalkerzone/atlas/atlas.schema.json`, проверки `AtlasValidator`):

| Поле | Смысл |
|---|---|
| `type` | тип территории: `forest`, `scrap`, `anomaly_field`, `lair`, `industrial`, `ruins`, `crossroads`, `underground` |
| `area` | многоугольник территории внутри `area` локации, без самопересечений |
| `features` | измеряемые особенности: `forest` (доля леса 0..1), `buildingArea`, `undergroundArea`, `roads`, `lairs`, `fields` (целые ≥ 0) |
| `potential` | силы 0..1 по ключам `wood`, `parts`, `artifacts`, `mutant`, `workshop`, `storage`, `trade`, `shelter`; ключей `food` и `water` нет — валидатор их запрещает |
| `buildings` | `[{ref: id объекта атласа}]` — существующие постройки TheZone внутри `area` зоны, пригодные под сектор |
| `parent` | необязательно: id объекта-узла своей локации (зона — данные узла-родителя, б3) |

У зоны **нет `node`** (она не узел симуляции: гарнизона, населения и склада товаров у неё нет) и **нет `site`**
(площадок и стройки нет). Статус зон Кордона — `observed`: невязка локации вне порога (Э1-06), границы
черновые, уточнение и утверждение — Э1-07/Э1-14. Номера узлов 0…23 не менялись: смена ролей узлов
(элеватор, ферма, вагончик, заставы туннеля) — отдельный заход Э1-07 → Э2-05, не эта задача.

## Потенциал выводится, а не назначается

`ru.stalkerzone.sim.TerritoryPotential.derive(type, features)` — единственное место, где появляются силы.
Атлас хранит результат вывода; `TerritoryPotentialTest` сверяет записанное с выведенным, поэтому
произвольные значения по зонам не проходят. Нормы (стартовые, баланс — Э7-01/Э8-07):
`BUILDINGS_NORM = 1000` колонок построек, `UNDERGROUND_NORM = 500` колонок подземных объёмов,
`ROADS_NORM = 3` дороги, `SCRAP_NORM = 500`, `RUINS_NORM = 300`.

Обозначения: `f` — доля леса, `b` = min(1, buildingArea/1000), `u` = min(1, undergroundArea/500),
`r` = min(1, roads/3), `l` = min(1, lairs), `p` = min(1, fields); силы округляются до 0,01, нулевые ключи не записываются.

| Ключ | Правило |
|---|---|
| `wood` | лес — дерево и стройматериалы: `forest` → `0.3 + 0.7f`, прочие типы → `0.7f` |
| `parts` | `scrap` → `0.5 + 0.5·min(1, buildingArea/500)`; `industrial` → `0.3b`; `ruins` → `0.3 + 0.4·min(1, buildingArea/300)`; прочие — 0 |
| `artifacts` | только `anomaly_field` → `0.4 + 0.6p` (артефакты после выбросов) |
| `mutant` | `lair` → `0.4 + 0.6l`; прочие типы с логовом внутри → `0.4l` (части и мясо мутантов — охота, Э9-06) |
| `workshop` | `industrial` → `0.4 + 0.6b`; прочие → `0.5b` (мастерская в существующих постройках) |
| `storage` | `0.6b + 0.3u` (склад в постройках и подземных объёмах) |
| `trade` | `crossroads` → `0.3 + 0.7r`; прочие → `0.4r` (торговля и пошлина на дороге) |
| `shelter` | `underground` → `0.4 + 0.6u`; прочие → `0.6u + 0.4b` (укрытие от выброса) |
| `food`, `water` | **запрещены**: еда и питьевая вода только привозные (Э8-08), вода в Зоне радиоактивна |

Стратегическая ценность `TerritoryPotential.strategicValue` = `0.30·trade + 0.25·artifacts + 0.20·shelter
+ 0.15·workshop + 0.10·parts` (округление до 0,01): позиция — дороги, артефакты, укрытие, мастерская;
дерево и склад — снабжение, не позиция. Пригодность к деятельности: `suitable(task)` = сила ключа задачи > 0.

## Особенности измеряются съёмкой

`tools/atlas/zone_features.py <mosaic.npz> <папка атласа> [локация]` — только чтение, печатает JSON особенностей
по каждой зоне. Классы поверхности и маска многоугольника берутся из `tools/thezone/survey_analyze.py`
(лес — листва/стволы/sapling; постройки — ≥ 3 искусственных блоков над землёй; подземные объёмы — `art_down ≥ 3`),
поэтому оценка совпадает со съёмкой Э1-04. Мозаика — вне git (`world/survey/mosaic.npz`).
Дороги, логова и поля считаются по атласу. Инструмент ничего не записывает: `features` переносятся в атлас
вручную (правка атласа — по правилам Э1-07), `potential` пересчитывается `derive` и проверяется тестом.

## Симуляция

- `sim/TerritoryKind`, `sim/TerritoryPotential`, `sim/TerritoryTask` — тип, вывод потенциала, локальные задачи
  (заготовка дерева, разборка техники, сбор артефактов, охота, мастерская, склад, торговля и пошлина, пост и укрытие).
- `sim/Territory` — территория: потенциал из атласа, владелец (`owner`, индекс группировки, −1 — ничья),
  локальная задача, день занятия, **природный запас** по ключам и день последней добычи.
- `sim/Territories` — реестр: `fromAtlas`, `occupy`, `release`, `assign`, `take`, `daily`, `write`/`read`.
- `Simulation.territories` — состояние живёт в симуляции и сохраняется секцией **v25** (`SAVE_VERSION` 24 → 25).
  `Simulation.step()` вызывает `territories.daily(day)` — только восстановление запаса.
- `ZoneData` определяет территории из атласа (`Atlas.loadResources`) при новом мире, сбросе и загрузке
  сохранения без секции; состояние занятия и запаса приходит из сохранения. Сервер — источник истины:
  занятие, освобождение и задачу меняет симуляция, игровой код вызывает её методы.

Правила занятия и задачи:

1. Занять можно **свободную** территорию с ненулевым потенциалом; чужую занятую — нельзя (захват — война, Э7-04).
2. При занятии фиксируются владелец и день; задача сбрасывается — новую назначает владелец.
3. Локальная задача назначается только владельцем и только **по потенциалу** (`suitable`); задачу можно снять.
4. Освобождение снимает владельца и задачу; запас зоны остаётся (природный ресурс не исчезает).
5. Добыча `take(id, task, workers, want, day)` требует владельца, совпадения с локальной задачей, людей и
   ненулевого потенциала; ограничена запасом зоны и `workers × YIELD_PER_WORKER` (2 единицы на человека в день).
6. Запас конечен: `capacity = сила × 100` единиц; восстановление `REGEN_PER_DAY = 0.05` запаса в день
   после `REGEN_DELAY_DAYS = 7` дней без добычи, не выше полного запаса.

**Запас территории — природный резерв, а не товар `Good`**: в `Ledger` и `Simulation.totals()` он не входит,
`audit()` не меняется. Владение территорией **не создаёт** людей, денег, оружия и товаров и не производит еду:
еда и вода остаются привозными (Э8-08), мясо мутантов — охота и разделка (Э9-06). Превращение добытого в товары
и запись прихода в Ledger — производство секторов (Э5-02, Э8-07); до тех пор добыча только уменьшает запас зоны.
Принадлежность территории не смешивается с `Node.owner`, гарнизонами (`Logistics.garrison`) и населением
(`NodePopulation`); Одиночки — группировка, вольные сталкеры — `Person.faction = none`, территории им не выдаются.

## Отложено (не входит в Э1-16)

- стройка и рост уровней — Э5-13/Э5-14; занятие использует существующие постройки TheZone;
- оценка зон мозгом группировки, разведка (уверенность ≥ 0,6), экспансия и потеря — Э7-04;
- производство секторов из сырья зоны через Ledger — Э5-02/Э8-07; снабжение и люди в секторе — Э2-15;
- смена ролей узлов Кордона (элеватор, ферма, вагончик, заставы туннеля) — Э1-07 → Э2-05, один сброс сохранения;
- удаление производства еды на узлах (`Node.farmCap`) — Э8-08 (в этом дереве еда ещё производится узлами);
- укрытия при выбросе по вместимости зданий — Э2-18.

## Проверки

- `TerritoryPotentialTest` (115 проверок) — потенциал по типам и особенностям, монотонность, запрет еды и воды (перебор типов
  и особенностей + негативные кейсы валидатора), зоны атласа и равенство `potential = derive(type, features)`,
  занятие/освобождение, локальная задача, конечный запас и восстановление, сохранение после перезапуска,
  отсутствие ресурсов и населения из воздуха (30 дней с занятыми территориями: снимок экономики, складов,
  владельцев узлов и населения совпадает с прогоном без территорий), аудит пуст.

- `SaveResetTest` — `SAVE_VERSION = 25`, Кордон прежней версии пересоздаётся с тем же сидом
