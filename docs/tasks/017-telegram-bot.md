# 017. Telegram-бот: уведомления о ходе работы и ежедневная сводка

**Линия: симуляция** (по факту инфраструктура: код мода, `build.gradle` и `sim/` не трогать).

Выполнять когда угодно, зависимостей нет. Модель: обычная.

Цель: человек не следит за GitHub, а получает в Telegram короткие сообщения после каждого шага конвейера
и сборки, плюс вечернюю сводку с расходами. Бот только отправляет сообщения (Bot API `sendMessage`),
команд не принимает, отдельный сервер не нужен.

## Секреты и переменные (заводит человек, в коде только читать)
- Секреты репозитория: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`.
- Уже есть: `OPENROUTER_API_KEY`, `PROXYAPI_KEY`.
- **Если `TELEGRAM_BOT_TOKEN` или `TELEGRAM_CHAT_ID` пусты, всё молча пропускается (код выхода 0).**
  Ошибка Telegram (сеть, 4xx) печатается в лог и тоже не роняет job, конвейер и сборку.

## Что сделать

### 1. `tools/notify/tg.py`: отправка (только стандартная библиотека, `urllib`)
- Использование: `python3 -I tools/notify/tg.py "текст"` или текст из stdin (`... | python3 -I tools/notify/tg.py -`).
- Обычный текст без `parse_mode` (чтобы не экранировать Markdown/HTML), `disable_web_page_preview=true`.
- Длиннее 4000 символов: обрезать, дописав `…(обрезано)`.
- Таймаут 20 с, одна повторная попытка.
- Первая строка каждого сообщения начинается с эмодзи статуса: ▶️ старт, ✅ успех, ❌ провал, ⚠️ нужен человек, 🔁 эскалация, 📊 сводка.

### 2. Уведомления из конвейера (`tools/conveyor/conveyor.sh`, `.github/workflows/conveyor.yml`)
Пробросить в шаг «Карточка» env `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`. В `conveyor.sh` добавить функцию
`tg() { python3 -I tools/notify/tg.py "$1" || true; }` и вызывать её в этих точках (логику конвейера не менять):

| Момент | Текст (пример) |
|---|---|
| взята карточка | `▶️ 012 Пост военных на мосту — старт (deepseek/deepseek-v4.1-flash)` |
| исполнитель закончил | `✅/❌ 012: исполнитель закончил, проверка: <первая строка-итог check.sh>` |
| эскалация к старшему | `🔁 012: тесты не прошли, подключаю старшего (claude-sonnet…)` + 5 последних строк проверки |
| вердикт ревью | `🔎 012: ревью — ОК` или `🔎 012: ревью — замечания, правит старший` |
| PR создан | `✅ 012: PR готов к слиянию — <URL>` (этапы `$PHASES`) |
| не справились | `⚠️ 012: нужен человек — <URL черновика PR>` + хвост проверки |
| нет карточки | `💤 Конвейер (<линия>): нет готовых карточек` |

Ссылку на запуск добавлять в конец сообщений о провале:
`$GITHUB_SERVER_URL/$GITHUB_REPOSITORY/actions/runs/$GITHUB_RUN_ID`.

### 3. Уведомления о сборке (`.github/workflows/build.yml`)
Последний шаг с `if: always()` и секретами Telegram: одно сообщение на пуш:
`✅/❌ сборка <ветка>: <первая строка сообщения коммита> (<автор>)` + ссылка на запуск.
Результат брать из `job.status`. Так видно и промежуточные `wip:`-пуши Cline при локальной работе.
Чтобы не спамить: для веток `task/*-auto` сообщать **только о провале** (успех и так придёт от конвейера).

### 4. Слияние PR
В `conveyor.yml` (или отдельным маленьким job в новом workflow `notify.yml` на `pull_request: closed`):
при `merged == true` → `🎉 PR #N слит: <заголовок>`.

### 5. Ежедневная сводка: `.github/workflows/daily-report.yml` + `tools/notify/daily_report.py`
- Запуск: `schedule: cron: '47 17 * * *'` (20:47 МСК) и `workflow_dispatch` для ручной проверки.
- `permissions: contents: read, pull-requests: read, actions: read`; данные брать через `gh` (`GH_TOKEN: ${{ github.token }}`).
- Содержимое (за последние 24 часа):
  1. **Работа**: слитые PR (номер, заголовок); открытые PR, включая черновики `needs-human` (⚠️);
     запуски `conveyor` и `build`: сколько успешных и упавших.
  2. **Карточки**: из таблицы `docs/tasks/README.md` посчитать `готово / всего` и перечислить, что следующее «ждёт»
     (можно переиспользовать разбор из `tools/conveyor/next_card.py`, без вызова git).
  3. **Расходы OpenRouter**: `GET https://openrouter.ai/api/v1/key` с `Authorization: Bearer $OPENROUTER_API_KEY` →
     поля `data.usage_daily`, `data.usage_weekly`, `data.usage_monthly`, `data.limit_remaining` (могут отсутствовать или быть `null`, тогда «—»).
     Дополнительно попробовать `GET https://openrouter.ai/api/v1/credits` (`total_credits - total_usage` = остаток счёта);
     при ошибке или 401/403 строку пропустить.
  4. **ProxyAPI**: попробовать `GET https://api.proxyapi.ru/proxyapi/balance` с `Authorization: Bearer $PROXYAPI_KEY`.
     Если 200 и в JSON есть число баланса, вывести его в ₽. Иначе написать `ProxyAPI: баланс по API недоступен`.
  5. Если за сутки не было ни одного запуска конвейера: строка `💤 Конвейер простаивал`.
- Любой из блоков может упасть (нет сети, поменялся API): тогда печатается `—`, а остальная сводка всё равно уходит.
- Без моделей ИИ: сводка собирается шаблоном, токены не тратятся.

Пример:
```
📊 Сводка за 31.10
Работа: слито 2 PR (#14 012 Пост военных, #15 013 Аномалии); открыт 1 (⚠️ #16 014 — нужен человек)
Запуски: конвейер 3 (✅2 ❌1), сборка 9 (✅8 ❌1)
Карточки: 9/17 готово; дальше: 014, 015
OpenRouter: сегодня $0.84, неделя $3.10, остаток ключа $1.90, счёт $17.40
ProxyAPI: 312 ₽
```

## Готово, когда
- `python3 -I tools/notify/tg.py "тест"` без секретов → код 0, в выводе «Telegram не настроен, пропуск».
- `daily_report.py` с переменной `DRY_RUN=1` печатает сводку в stdout вместо отправки; при запуске без
  `OPENROUTER_API_KEY`/`PROXYAPI_KEY` не падает, в этих строках «—».
- `bash -n tools/conveyor/conveyor.sh` без ошибок; логика конвейера (порядок этапов, коды выхода, PR) не изменилась.
  Все вызовы `tg` с `|| true`.
- YAML новых и изменённых workflow валиден (`python3 -c "import yaml,sys; yaml.safe_load(open(sys.argv[1]))" файл`, если `yaml` есть).
- Тесты симуляции и сборка проходят (`bash tools/conveyor/check.sh`). PR с блоком передачи смены.
