# Как подключить ИИ-команду к разработке (Windows)

## Кто что делает
| Роль | Кто | Что делает |
|---|---|---|
| Заказчик и тестер | вы | запускаете карточки в Cline, сливаете PR, играете и пишете, что не так |
| Исполнитель | Cline + модель через OpenRouter | выполняет **одну** карточку из `docs/tasks/` = один PR |
| Архитектор | Claude (этот чат) | пишет карточки, импортирует уровни из игры (карточка 004), ревью на вехах, сложные баги |

Правила для исполнителя лежат в `.clinerules` в корне репозитория — Cline читает их сам, вставлять в чат не нужно.

## 1. Программы (один раз)
1. **Git for Windows** — https://git-scm.com/download/win, всё по умолчанию.
2. **JDK 17** (Temurin) — https://adoptium.net, версия 17, при установке включить «Set JAVA_HOME».
   Проверка в PowerShell: `java -version` → `17.x`.
3. **GitHub CLI** — https://cli.github.com, затем в PowerShell: `gh auth login` → GitHub.com → HTTPS → браузер.
4. **VS Code** — https://code.visualstudio.com.
5. Python и WSL **не нужны**: уровни из игры импортирует Claude.

## 2. Репозиторий
```powershell
cd C:\MineStalker
git clone https://github.com/Grilik/stalkerzone sz
cd sz
git config user.name "Grilik"
git config user.email "ваша почта на GitHub"
```
Старую папку `C:\MineStalker\stalkerzone` больше не используйте для сборки — работаем только в `C:\MineStalker\sz`.
В VS Code: File → Open Folder → `C:\MineStalker\sz`.

Проверка, что всё собирается (до первой карточки):
```powershell
powershell -ExecutionPolicy Bypass -File tools/simtest.ps1
./gradlew.bat build
```
Оба шага должны закончиться без FAIL/ошибок. Если нет — пришлите Claude последние 30 строк вывода.

## 3. OpenRouter
1. https://openrouter.ai/keys → Create Key. **Задайте лимит ключа** (Credit limit), например $5:
   агент в цикле не потратит больше.
2. Скопируйте ключ (`sk-or-...`), он показывается один раз.

## 4. Cline
Названия кнопок могут немного отличаться в разных версиях Cline — ищите по смыслу.

### 4.1 Установка
1. VS Code → слева значок «квадратики» (Extensions) или Ctrl+Shift+X.
2. В поиске `Cline` → расширение от **Cline** (saoudrizwan.claude-dev, миллионы установок) → Install.
3. Слева появится значок Cline (робот). Нажмите его — откроется панель Cline.
   Если Cline предлагает войти в свой аккаунт — выберите вариант «Use your own API key» / «Bring your own key».

### 4.2 Провайдер и ключ
1. В панели Cline вверху — шестерёнка (Settings) → раздел **API Configuration**.
2. **API Provider** → `OpenRouter`.
3. **OpenRouter API Key** → вставить ключ `sk-or-...` из п. 3.

### 4.3 Модели Plan и Act
У Cline два режима: **Plan** — читает код и пишет план, ничего не меняя; **Act** — правит файлы и запускает команды.
1. Включите галочку **Use different models for Plan and Act modes**. Появятся две вкладки: Plan Mode и Act Mode.
2. Вкладка **Act Mode** → поле **Model** → начните печатать `deepseek` → выберите `deepseek/deepseek-v4.1-flash` (V4 Pro в 12 раз дороже и не лучше).
3. Вкладка **Plan Mode** → тоже `deepseek/deepseek-v4.1-flash`.
4. Для тяжёлых карточек (в `README.md` карточек помечены «сильная модель для плана»: **009** и **014**)
   перед запуском переключите **Plan Mode** на `z-ai/glm-5.3` (дешевле) или `anthropic/claude-sonnet-5.5` (лучше, дороже).
   Act оставьте на DeepSeek. После карточки верните Plan на DeepSeek.
5. Если нужной модели нет в списке — наберите часть названия (`glm`, `sonnet`, `deepseek`) и возьмите самую новую версию
   без `:free` (бесплатные варианты ограничены по скорости и пропадают). Цена за 1M токенов видна под названием.
6. Остальное в настройках не трогайте (температура, Extended thinking — по умолчанию).

### 4.4 Автоодобрение
Над полем ввода в панели Cline — строка **Auto-approve**. Нажмите на неё, раскроется список:
| Пункт | Ставить | Почему |
|---|---|---|
| Read project files | ✔ | агент читает код без подтверждения |
| Read all files | ✘ | файлы вне проекта ему не нужны |
| Edit project files | ✔ | правки видны в чекпоинтах, их можно откатить |
| Edit all files | ✘ | вне проекта ничего не правит |
| Execute safe commands | ✔ | сборка, тесты, git status — Cline сам решает, что «безопасно» |
| Execute all commands | ✘ | удаление, установка программ, push — только с вашего «да» |
| Use the browser | ✘ | не нужен |
| Use MCP servers | ✘ | не нужен |
| **Max Requests** | 40 | после 40 шагов подряд Cline остановится и спросит — защита от зацикливания и трат |

Когда Cline спрашивает разрешение на команду — читайте её: `gradlew`, `git add/commit/push`, `gh pr create`,
`powershell -File tools/...` — можно. `rm`, `del`, `Remove-Item` вне `build/` и `run/`, `git reset --hard`,
`git push --force`, правка `build.gradle` — отклоняйте (Reject) и пишите агенту, почему.

### 4.5 Чекпоинты и контекст
1. В настройках включены **Checkpoints** (по умолчанию да). У каждого шага агента есть кнопки **Compare** (что изменилось)
   и **Restore** (откатить файлы к этому месту).
2. Вверху панели — полоса контекста (сколько токенов занято). Подбирается к ~60–70% — агент начнёт тупить: пусть сделает
   коммит текущего, затем **New Task** с текстом «Продолжи карточку NNN, сделано: …».
3. Внизу панели видна цена текущей задачи ($). Нормально для карточки: $0.1–1 на DeepSeek. Ушло за $2 — остановите и разберитесь.

## 5. Цикл одной карточки
1. Выберите в `docs/tasks/README.md` первую карточку со статусом «к выполнению», у которой выполнены зависимости.
2. PowerShell в папке `sz`:
   ```powershell
   git checkout main; git pull
   git checkout -b task/005-war-balance
   ```
3. В Cline — **New Task**, режим **Plan**, текст:
   > Выполни docs/tasks/005-kordon-war-balance.md. Сначала прочитай карточку, .clinerules и код,
   > который она упоминает. Дай план по пунктам «Готово, когда».
4. Прочитайте план. Если агент собирается трогать то, что в разделе «Не делать», напишите ему об этом. Затем **Act**.
5. Когда агент закончит, проверьте сами:
   ```powershell
   powershell -ExecutionPolicy Bypass -File tools/simtest.ps1
   ./gradlew.bat build
   ```
6. Попросите Cline: «Сделай коммит и PR по правилам .clinerules». Или сами: `git add -A; git commit -m "..."; git push -u origin HEAD; gh pr create --fill`.
7. На GitHub дождитесь зелёной галочки CI у PR → **Squash and merge**. В `docs/tasks/README.md` статус карточки поменяет агент в том же PR.
8. Следующая карточка — **новая задача** в Cline (не продолжайте старую: длинный контекст дорогой и тупит модель).

## 6. Когда агент буксует
- 3 неудачных попытки починить одну ошибку → Stop. Откатите чекпоинт, запустите карточку заново на сильной модели (п. 4.3).
- Не помогло → в этот чат Claude: номер PR (или ветки) и **последние 30–50 строк** ошибки. Не вставляйте логи целиком.
- Агент правит `build.gradle`, `gradle.properties`, `world/xray`, `tools/xray` без указания в карточке — отклоняйте.
- Карточки с «модель: Claude» делает архитектор сам — в Cline их не запускать.

## 7. Вехи — когда звать Claude
Ревью пачкой, а не каждого PR (экономия лимита Claude):
- **Веха 1** — после 001–003 и 005–007 (вся симуляция Кордона): «ревью вехи 1, PR #… – #…».
- **Веха 2** — после 004 и 008–011 (мир и старт игрока).
- **Веха 3** — после 012–015: Claude проверяет на сервере, собирает jar и ставит вам на ПК; затем ваш плейтест (016).
Claude проверяет CI, тесты и смоук-тест на сервере и пишет карточки-исправления, если что-то не так.

## 7а. Автоматический ревьюер PR
Каждый PR проверяет другая модель (по умолчанию `z-ai/glm-5.3-flash` через OpenRouter) и пишет комментарий: вердикт,
пункты карточки, проблемы. Плюс механические блокеры: лишние файлы, импорт Minecraft в `sim`, правка `build.gradle`.
- Ключ: GitHub → репозиторий → Settings → Secrets and variables → Actions → **New repository secret**,
  имя `OPENROUTER_API_KEY`, значение — ключ OpenRouter (можно отдельный, с лимитом $2).
- Сменить модель: там же вкладка **Variables** → `REVIEW_MODEL`, например `qwen/qwen3.8-max`.
- Вердикт «БЛОКЕР» или «ЕСТЬ ЗАМЕЧАНИЯ» — скопируйте комментарий агенту в Cline: «Исправь замечания ревью: …».

## 7б. Конвейер на GitHub (без вашего ПК)
Workflow `conveyor` выполняет карточки сам на серверах GitHub:
0. Две линии параллельно — **симуляция** и **мир** (метка «Линия» в карточке).
1. Cline CLI делает карточку: `AGENT_MODEL` (по умолчанию `deepseek/deepseek-v4.1-flash`), для карточек с меткой
   «Модель исполнителя: сильная» — `AGENT_MODEL_STRONG` (по умолчанию та же Flash; V4 Pro конвейер игнорирует ради экономии).
   Если одна ошибка не уходит после 3 попыток — он не крутится, а пишет `ESCALATE.md` и останавливается.
2. Конвейер сам гоняет тесты и сборку (`tools/conveyor/check.sh`).
3. Провал → **старшая модель** Claude через ProxyAPI (секрет `PROXYAPI_KEY`, переменная `STRONG_MODEL`, по умолчанию `anthropic/claude-sonnet-5-5`) получает только суть:
   описание проблемы, список файлов и хвост ошибки — и чинит минимально. Короткий контекст = дёшево.
4. Ревьюер; замечания → старшая модель исправляет обоснованные.
5. PR. **Сливаете вы** (Merge). После слияния конвейер сам берёт следующую карточку,
   кроме вех 006, 011, 015 — там ждёт архитектора.
6. Не справился и старший → черновик PR с меткой `needs-human` и упоминанием вас (придёт письмо) → ссылку архитектору.

Запуск вручную: GitHub → Actions → **conveyor** → **Run workflow** (номер карточки можно не указывать).
Модели меняются в Settings → Secrets and variables → Actions → Variables: `AGENT_MODEL`, `STRONG_MODEL`.
Деньги: тот же секрет `OPENROUTER_API_KEY`; поставьте ключу лимит, например $15.
Не запускайте конвейер на карточку, которую сейчас делает Cline на ПК (конвейер пропускает карточки, у которых уже есть ветка `task/NNN-*` на GitHub).

## 7в. Telegram-бот (уведомления и сводка)
Бот пишет в Telegram после каждого шага конвейера (старт карточки, итог исполнителя, подключение старшего, ревью,
PR готов / ⚠️ нужен человек), после каждой сборки (для веток `task/*-auto` — только о провалах), о слиянии PR,
и каждый вечер в 20:47 МСК присылает 📊 сводку: PR и запуски за сутки, карточки, расходы OpenRouter и ProxyAPI.
ИИ для этого не используется — сообщения собираются шаблоном.

Подключение (один раз):
1. В Telegram: @BotFather → `/newbot` → получить токен. Написать своему боту `/start`.
2. Узнать свой chat_id: написать @userinfobot.
3. GitHub → Settings → Secrets and variables → Actions → секреты `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.
4. Проверка: Actions → **daily-report** → Run workflow — через минуту придёт сводка.

Без секретов всё молча пропускается. Код: `tools/notify/tg.py` (отправка), `tools/notify/daily_report.py`
(сводка; `DRY_RUN=1` — печать без отправки), workflow `daily-report.yml`, `notify.yml`, шаг Telegram в `build.yml`.
**Команды боту** (ответ в течение ~30 минут — сервера нет, GitHub проверяет сообщения по расписанию):
`/баг текст` и `/идея текст` — issue на GitHub; `/статус` — конвейер, открытые PR, баланс; `/сводка`;
`/запуск` или `/запуск 012` — запустить конвейер; `/помощь`.

**Сборка для игры:** после каждого зелёного `main` jar выкладывается в Releases → `nightly`, ссылка приходит в Telegram (🎮).

**Бюджет:** конвейер не начинает карточку, если на OpenRouter осталось меньше `MIN_BALANCE` (по умолчанию $2;
меняется в Settings → Secrets and variables → Actions → Variables). В PR и сообщении «PR готов» — стоимость карточки.

Важно: конвейер не может менять файлы в `.github/workflows` (запрет GitHub для токена Actions) — такие карточки
выполняет Claude или Cline на ПК.

## 7г. Claude по подписке вместо ProxyAPI
Если задан секрет `CLAUDE_CODE_OAUTH_TOKEN`, старший в конвейере — Claude Code по подписке Claude (без оплаты токенов,
расходует лимит подписки). Не больше `CLAUDE_DAILY_LIMIT` вызовов в сутки (по умолчанию 5; сбросить счётчик — переменная `CLAUDE_RESET_AT` = текущее время UTC, напр. `2026-11-01T09:00:00Z`) — дальше карточка уходит человеку.
Без токена — по-старому, через ProxyAPI.
Токен: на ПК установить Claude Code (`irm https://claude.ai/install.ps1 | iex` или `npm install -g @anthropic-ai/claude-code`),
затем `claude setup-token` → скопировать токен в секрет. Токен никому не пересылать.

`@claude текст` в комментарии к PR/issue (только от владельца репозитория) — Claude Code отвечает и может поправить ветку PR.

**Выключатель конвейера:** Settings → Secrets and variables → Actions → Variables → `CONVEYOR_PAUSED` = `1`
(остановить; новые запуски не стартуют даже после слияния PR). Удалить или поставить `0` — работа продолжится.

## 7д. Автослияние и конфликты
Замечания ревью правит дешёвый исполнитель; Claude зовётся только на «БЛОКЕР» и механические блокеры (экономия лимита подписки).
Перед PR конвейер вливает свежий `main` в ветку карточки. Конфликт чинит исполнитель, не справился — старший;
не вышло — откат и PR без автослияния. После совмещения тесты прогоняются заново.
PR сливается сам, если: тесты зелёные, ревью «ОК» или «ЕСТЬ ЗАМЕЧАНИЯ» после раунда правок (но не «БЛОКЕР»), карточка не веха (006, 011, 015), main совмещён.
После автослияния конвейер сам запускает сборку main (🎮) и следующую карточку своей линии. Иначе — 👀 в Telegram с причиной.
Выключить автослияние: переменная `AUTO_MERGE` = `0`. Плохое слияние — кнопка **Revert** в PR.

## 8. Частые проблемы
- `gh: command not found` — перезапустите VS Code после установки GitHub CLI.
- Gradle ругается на версию Java — `java -version` должна быть 17; иначе переустановите Temurin 17 с JAVA_HOME.
- Кракозябры в выводе PowerShell — `chcp 65001` перед командами.
- PowerShell не запускает .ps1 — добавляйте `-ExecutionPolicy Bypass`, как в командах выше.
- OpenRouter 402/лимит — пополните баланс или поднимите лимит ключа.
