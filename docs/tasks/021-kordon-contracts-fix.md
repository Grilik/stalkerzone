# 021. Контракты Кордона: заказы Бандитов и касса для «засады на встречу»

**Линия: симуляция.**

Выполнять после 006. Модель: обычная. Доделка по ревью PR #19 (карточка 006, слита с замечаниями).

## Что сделать
1. **Заказчики-Бандиты** (в `ContractBoard.generateKordon`, по аналогии с Торговцами/Одиночками/Военными, через `issueCash`):
   - «Засада на курьера» — новый тип `AMBUSH_COURIER` («Засада на курьера»): цель — курьер/караван Торговцев,
     который сейчас в пути. Успех — курьер не дошёл (груз пропал у получателя, как при обычном нападении).
   - «Налёт на ферму» — новый тип `RAID_NODE` («Налёт»): цель — Свиноферма (или другой узел с `farmCap > 0`,
     не принадлежащий бандитам). Успех — узел потерял запасы еды (часть склада уходит бандитам), владелец не меняется.
   - Оба типа — **только для игрока-бандита** (как в карточке 006): NPC их не берут (`npcTake` — исключить).
   - Новые значения enum `Contract.Type` — **строго в конец** списка. Формат сохранения не меняется (тип пишется как сейчас);
     если пишется ординалом — поднять версию сохранения и сохранить чтение v16.
   - Шансы, награды, сроки — константы в `KordonBalance` (рядом с остальными контрактами), без моих цифр «из воздуха»:
     награды порядка `REWARD_ESCORT`.
2. **AMBUSH_MEETING на Кордоне** (`meetingContracts`, путь `kordonAmbusher`) выдавать через `issueCash`:
   нет денег у заказчика — контракт не выставляется (п. 3 карточки 006).
3. Тест: расширить тест контрактов из 006 (или `ContractsKordonTest`): за 30 дней у Бандитов появляется хотя бы один
   `AMBUSH_COURIER` или `RAID_NODE`; NPC их не берут; при пустой кассе заказчика `AMBUSH_MEETING` не выставляется.
