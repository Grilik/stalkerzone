# 026. Контракты игрока: никто не отбирает, счётчик целей

**Линия: симуляция.** (UI КПК — минимально, в существующей вкладке «Задания».)

Модель: обычная. Плейтест: игрок взял контракт на логово, пострелял мутантов — задание не выполнилось и «ушло одиночкам».
Правило: **NPC могут выполнять контракты, но не отбирают их у игрока.**

## Что сделать
1. Найти, как контракт игрока (`taker == PLAYER`, статус `TAKEN`) становится чужим/закрытым: `ContractBoard` — истечение
   (`deadline`), закрытие `CLEAR_LAIR` при `lairAt(node) == null`, `npcTake`, перегенерация. Исправить так, чтобы:
   - взятый игроком контракт не может взять NPC и не может закрыться в пользу NPC;
   - если логово уничтожил кто-то другой, пока контракт у игрока, — контракт игрока **засчитывается игроку**, только если
     игрок нанёс логову урон (убил хотя бы одного мутанта логова); иначе — «сорван» с возвратом залога заказчику и
     сообщением игроку, а не тихое исчезновение;
   - срок контракта игрока на логово — не меньше 5 игровых дней (константа в `KordonBalance`).
2. **Счётчик целей:** у `CLEAR_LAIR` хранить, сколько мутантов логова осталось / сколько убил игрок; убийство мутанта
   логова игроком уменьшает счётчик (событие уже есть: `PlayerFaction.onMutantKilled`). В КПК («Задания») строка
   «Мутанты: убито N из M», в чат при каждом убийстве — короткое «Логово: осталось K».
   Поле в сохранение — поднять версию сохранения, чтение старых версий оставить.
3. Метка логова цели на карте КПК (если ещё нет).
4. Тест: игрок берёт `CLEAR_LAIR`; 10 дней NPC не забирают его; уничтожение логова NPC без участия игрока → контракт
   «сорван», залог вернулся; с участием игрока → `READY`.
