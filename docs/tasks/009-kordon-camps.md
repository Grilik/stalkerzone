# 009. Узлы на постройках уровня: без генерации поверх

**Линия: мир.** **Шаблон локации:** всё, что здесь сказано про Кордон, реализуй через данные локации (файл точек `data/stalkerzone/points/<levelId>.json` и узлы сценария), без хардкода Кордона в коде мира — следующие локации должны заработать только добавлением их файла точек. Кордон — первый экземпляр.
**Модель исполнителя: сильная.**

Выполнять после 004 и 008. Модель: сильная (план).

## Зачем
Базы Кордона — это настоящие здания уровня (деревня, АТП, блокпосты, элеватор, ферма). Генератор лагерей не должен
строить свои дома поверх них, а NPC должны жить в этих зданиях.

## Что сделать
1. Обобщи `KordonPoints` из 004 в `world/LevelPoints.java`: `LevelPoints.forLevel(levelId)` читает
   `data/stalkerzone/points/<levelId>.json`; перенеси `kordon_points.json` → `points/l01_escape.json` (формат не менять).
   Код мира берёт точки узла через сценарий (узел → уровень → точки), а не через `KordonPoints`.
2. В сценарии `kordon` для узлов с точками `Camp` **не ставит постройки**: только мелочь — костёр, флаг фракции, ящики, лежанки
   на точках `campfire`/`flag`/`beds`. Смена владельца меняет флаг и окраску (как сейчас в `Camp`).
3. `NpcManager` ставит NPC узла на точки `beds`/`campfire`/`guards`, патрули ходят по `patrol`.
4. `WorldDecorator` и `LandmarkManager` не работают внутри региона уровня (иначе фоновые кучи хлама и чужие ориентиры).
5. Узлы-места логов из 007 (`LAIR_SITES` в `KordonScenario`) — без лагеря и флага: только мутанты (карточка 014).
6. Построечные уровни/ремонт для узлов уровня — отключить в 1.0 (запись в «Решения» PR).
