# Полные задачи для Qwen

Каждая задача — по падающему тесту. Тест уже в репозитории и **красный**; правка кода — только чтобы он позеленел,
без ослабления проверок.

**Как устроены тесты в проекте (важно!):** JUnit нет. Каждый `src/test/java/<Имя>Test.java` — обычный класс
с `public static void main`, счётчиком `f` и `ck(условие, сообщение)`; падение = `System.exit(1)`.
Все тесты компилируются **одним** `javac`:

```bash
mkdir -p out
javac --release 17 -encoding UTF-8 -d out $(bash tools/ci/test_sources.sh)
java -Dfile.encoding=UTF-8 -cp out NodeCountTest
```

Поэтому новый тест обязан компилироваться сразу; если проверяешь поле, которого ещё нет, — читай его по имени
(`getDeclaredField`) и падай по условию, а не ошибкой компиляции.

## К1 (Э4-07): NodeCountTest — массивы по числу узлов

**Тест:** `src/test/java/NodeCountTest.java` (красный).
**Вспомогательное:** `src/test/java/BigAtlas.java` — синтетический атлас (сетка узлов), его менять не нужно.

**Что сейчас не так:** `People.zombies`, `Politics.cutDays`, `Simulation.knowledge` созданы как `new ...[64]`.
На Кордоне 24 узла — ошибка не видна; на 300 узлах падает:

```
java.lang.ArrayIndexOutOfBoundsException: Index 64 out of bounds for length 64
    at ru.stalkerzone.sim.Simulation.seedAnomalies(Simulation.java:401)
```

**Что делать:** размеры этих массивов — от `nodes.size()`. Поля объявлены как `final` и инициализируются
inline, а `nodes` известен только в конструкторе `Simulation`; поля `People`/`Politics` создаются там же
(`new People()`, `new Politics()` — поля `Simulation`). Заведи у `People` и `Politics` метод инициализации
(например, `init(int nodeCount)`) и вызови его из конструктора `Simulation`, а `knowledge` создавай в конструкторе.
`grep -n "= new .*\[64\]" src/main/java/ru/stalkerzone/` — других жёстких 64 в `sim/` нет, но проверь ещё
`grep -rn "MAX_NODES" src/main/java/ru/stalkerzone/sim/`.

**Приёмка:**
- `java -cp out NodeCountTest` → «ВСЕ ПРОВЕРКИ ПРОЙДЕНЫ».
- Весь набор зелёный, кроме `MutantLedgerTest` (это К16, отдельная задача): прогон — цикл из `README.md`.
- Ни один существующий тест не падает; симуляция на Кордоне даёт те же числа, что до правки.

**Ограничения:** логику симуляции не менять — только размеры массивов. Сохранения: индексы не сдвигаются,
формат `SAVE_VERSION` не трогать.

## К15 (Э4-09): ZoneBenchTest — бенчмарк 400 узлов

**Тест:** `src/test/java/ZoneBenchTest.java` (красный). Быстрый режим: 30 дней × 3 сида.
Полный (ночной): `java -Dbench.full=true -cp out ZoneBenchTest` — 365 дней.

**Что нужно:** мир на 400 узлов должен создаваться и жить. Сейчас падает на создании — та же ошибка
`Index 64`, что и в К1. **Сначала К1**, потом этот тест; отдельного кода под К15, скорее всего, не нужно.

Тест проверяет три вещи:
1. нет исключений и `audit()` пуст каждый день (книги `Ledger` сходятся);
2. одинаковый сид → одинаковая подпись состояния (`BigAtlas.signature`);
3. медиана суточного шага ≤ 15 мс (Э4-09), печатается медиана и 99-й перцентиль.

**Приёмка:**
- `java -cp out ZoneBenchTest` → «ВСЕ ПРОВЕРКИ ПРОЙДЕНЫ», весь прогон ≤ 60 с.
- Медиана шага в выводе — записать в отчёт задачи.
- Если медиана > 15 мс — **не ослаблять порог**, а сообщить Claude: нужен режим планировщика «фаза за тик»
  (Э4-01), это отдельное решение.

**Ограничения:** числа `Ledger` не подкручивать; `audit()` не отключать; порог 15 мс не менять.

## К16 (Э8-10): MutantLedgerTest — книга мутантов

**Тест:** `src/test/java/MutantLedgerTest.java` (красный на последней проверке).
Формула `Lair.mutantCount()` и кормление уже зелёные — их не трогать.

**Что нужно:** третья книга `Ledger` — мутанты. Сейчас `Simulation` считает только число логов
(`lairsSpawned`, `lairsDestroyed`), а мутантов — нет.

**Договорённые имена** (тест читает их по имени, так что переименование = падение):
- `Ledger.mutantsBorn` — сколько мутантов появилось (`long`);
- `Ledger.mutantsDied` — сколько погибло (`long`).

Правило: Σ`mutantCount()` по всем логовам = старт + `mutantsBorn` − `mutantsDied`, каждый день.
Рождение — когда `mutantCount()` логова вырос (в т.ч. новое логово: его мутанты — «родились»),
смерть — когда упал (зачистка, голод, налёт). Считать раз в день после `lairsDaily()`, сравнивая
сохранённый снимок по логовам.

**Приёмка:**
- `java -cp out MutantLedgerTest` → «ВСЕ ПРОВЕРКИ ПРОЙДЕНЫ».
- 180 дней Кордона: `born + died > 0` и равенство сходится.
- Книга **не** ломает `audit()` (товары/деньги) и не входит в его инвариант — она отдельная.
- Сохранение: счётчики дописать в конец (`SAVE_VERSION` +1, чтение старых — нулями).

**Ограничения:** `Lair.mutantCount()` и `feed()` не менять; `MAX_MUTANTS` не трогать.
