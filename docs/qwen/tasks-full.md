## К1 (Э4-07): NodeCountTest

**Статус:** ⏳ Ожидание написания теста (этап 1.3).

### Падающий тест

```java
// src/test/java/ru/stalkerzone/sim/NodeCountTest.java
// Написать в этапе 1.3
```

### Описание

Узлы симуляции (районы Кордона) хранятся в массиве. Тест проверяет, что все массивы в `Faction`, `Group`, `Ledger` калибруются под `nodes.size()`, не жёсткая 64.

**Где:** `src/main/java/ru/stalkerzone/sim/` (Faction, Group, Ledger, ...)

**Что трогать:** конструкторы и `load()` методы, проинициализировать массивы на `nodes.size()`.

### Приёмка

- ✅ Тест зелёный после правки
- ✅ CI проходит (`./gradlew build`)
- ✅ RNG хеши совпадают: `KordonBalanceTest`, `ZoneBalanceTest` (если есть)
- ✅ Код следует стилю репозитория

### Ограничения

- Не менять логику симуляции, только размеры массивов
- Не трогать `KordonBalance.START_LAIRS`, `KordonBalance.START_GROUPS`
- Не менять сид в тестах

## К15 (Э4-09): ZoneBenchTest

**Статус:** ⏳ Ожидание написания теста (этап 1.3).

### Падающий тест

```java
// src/test/java/ru/stalkerzone/sim/ZoneBenchTest.java
// Написать в этапе 1.3
```

### Описание

Бенчмарк симуляции на синтетическом атласе: 400 узлов, 40 фракций, 1000 групп, 10 000 персонажей. Проверяет, что симуляция работает на большом масштабе.

**Где:** `src/test/java/ru/stalkerzone/sim/`, `src/main/java/ru/stalkerzone/atlas/` (если нужен синтетический граф).

**Что писать:** 
1. Генератор синтетического атласа (400 узлов в сетке, рёбра между соседями)
2. Инициализация симуляции
3. Цикл 1000 тиков
4. Проверка: никакие ошибки, персонажи живы, репутация считается

### Приёмка

- ✅ Тест зелёный, завершается за < 5 сек
- ✅ CI проходит
- ✅ RNG хеши предсказуемы (сид фиксирован)
- ✅ Производительность: < 100 ms на тик в среднем

### Ограничения

- Не добавлять реальные данные из `KordonBalance` (это бенчмарк, не интеграционный тест)
- Не менять основной симуляционный код

## К16 (Э8-10): MutantLedgerTest

**Статус:** ⏳ Ожидание написания теста (этап 1.3).

### Падающий тест

```java
// src/test/java/ru/stalkerzone/sim/MutantLedgerTest.java
// Написать в этапе 1.3
```

### Описание

Ledger ведёт счётчики мутантов по видам (Псевдособака, Псевдогигант, Бюрер, ...). Тест проверяет, что счётчики корректно обновляются при спауне, смерти, изменении статуса.

**Где:** `src/main/java/ru/stalkerzone/sim/Ledger.java`, `src/main/java/ru/stalkerzone/sim/Mutant.java`.

**Что писать:**
1. Инициализировать Ledger с пустыми счётчиками
2. Спаунить несколько видов мутантов, проверить счётчики
3. Убить мутантов, проверить убыль
4. Проверить сумму всех счётчиков = живым мутантам

### Приёмка

- ✅ Тест зелёный
- ✅ CI проходит
- ✅ Счётчики не теряют данные между тиками
- ✅ Нет утечек памяти (не критично, но желательно)

### Ограничения

- Не менять интерфейс Ledger (только реализация внутри)
- Не трогать Mutant.spawn(), Mutant.die()
