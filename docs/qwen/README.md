# Qwen Code — параллельная работа с Claude

**Статус:** этап 1.2 (инфраструктура, 18.11.2026).

Это рабочий каталог для интеграции Qwen Code как параллельного исполнителя задач мода Stalker Zone. Целевой результат — экономия лимита Qwen Plus (фиксированный месячный бюджет токенов) и ускорение работы.

## Структура файлов

- **`README.md`** — этот файл, правила и справка
- **`tasks-full.md`** — очередь полных задач для Qwen (с кодом, тестами, приёмкой)
- **`tasks-short.md`** — однострочные промпты для CLI (`qwen-code < prompts.txt`)
- **`progress.md`** — таблица оценки выполненных работ (статус, результат, когда, примечание)

## Циклы работы

### Цикл 1: Пилот (К1, К15, К16 — 3 К-карты)

Напишу 3 падающих теста (этап 1.3), запущу Qwen на них:

1. **К1 (Э4-07)** — `NodeCountTest.java` (массивы по `nodes.size()`, не 64)
2. **К15 (Э4-09)** — `ZoneBenchTest.java` (синтетический бенчмарк с атласом 400 узлов)
3. **К16 (Э8-10)** — `MutantLedgerTest.java` (счётчики мутантов в Ledger)

**Когда:** После написания тестов (этап 1.3). На пилоте Qwen решит 3 задачи, вернёт PR. Claude проверит, слит.

### Цикл 2: Остальные К-карты (13 шт., 49 задач)

После успеха пилота напишу тесты для остальных 13 К-карт (соответствуют 49 задач конвейера). Их выполнит Qwen параллельно.

### Цикл 3: Долгие задачи (39 основных + спецзадачи)

После активации конвейера v2 Qwen будет получать длинные задачи (построение, симуляция, интеграция) через dispatcher.

## Правила для Qwen

### Что может делать

- ✅ Писать код по падающему тесту (от Read красного теста к зелёному коду)
- ✅ Редактировать файлы, создавать новые
- ✅ Коммитить, пушить в ветку (не в main)
- ✅ Собирать (`./gradlew build`), запускать тесты (`./gradlew test`)
- ✅ Советоваться с Claude (ведущий) если неясно или нужен дизайн

### Что нельзя делать

- ❌ Мергить PR в main (только Claude или автомат после CI)
- ❌ Пушить в main напрямую (через PR)
- ❌ Удалять файлы (без явного разрешения)
- ❌ Трогать `C:\MineStalker\The Zone\` (оригинальный мир) и `*.szl` файлы
- ❌ Менять `level-type`, `seed` в тестах без согласования

### Стиль кода и сообщения

- Язык коммитов и PR описания: русский
- Стиль: следовать существующему коду в репозитории
- В начало PR названия — номер задачи из `docs/roadmap.md` (например, `К1: …`, `К15: …`)
- Конец коммит-сообщения: `Co-Authored-By: Qwen Code <noreply@alibaba.com>`
- Конец PR описания: `🤖 Generated with Qwen Code`

## Лимит и экономия

**Qwen Plus:** фиксированный месячный бюджет токенов (не pay-as-you-go).

**Экономия:**
- Одна задача ≈ 50K–200K токенов (код, тесты, коммит)
- Пилот (3 К-карты) ≈ 200–500K
- Цикл 2 (13 К-карт) ≈ 2–4M
- На всё модно остаться в рамках месячного лимита

**Следить:** каждую сессию обновляю `progress.md` со статусом, расходом, примечаниями.

## Модели Qwen

| Модель | Context | Output | Цель |
|--------|---------|--------|------|
| `qwen-turbo` | 256K | 8K | Маленькие задачи, быстро |
| `qwen-plus` | 256K | 4K | Средние, экономно |
| `qwen-flash` | 128K | 4K | Очень быстро, тесты |
| `qwen-max` | 256K | 8K | Сложное, архитектура (редко) |

По умолчанию — `qwen-plus` для всех. Если задача упирается в context или output, переходим на `qwen-turbo` / `qwen-max`.

## Инструменты для работы

- **Dispatcher (этап 1.3):** `tools/qwen/dispatch.py` — заполняет `tasks-short.md`, запускает Qwen Code CLI, слеживает результаты
- **Dashboard (этап 1.2):** `tools/dashboard/build.py` парсит `progress.md`, выводит таблицу на `#qwen` страницы

## Глоссарий

- **К-карта** — карточка задания Fable, вроде `К1 (Э4-07)`, `К15 (Э4-09)`, `К16 (Э8-10)`. Всего 16 К-карт для конвейера.
- **Падающий тест** — красный тест, который не проходит; Qwen пишет код, чтобы стал зелёным.
- **PR** — Pull Request; после Qwen пишет код и пушит, создаёт PR → Claude проверяет → мергит.
- **RNG детерминизм** — хеши случайности должны совпадать (KordonBalanceTest, ZoneBalanceTest); это проверяет, что симуляция не изменилась.
- **Конвейер v2** — автоматический цикл: тест → Qwen решает → PR → Claude проверяет → слит.
