# К2 — Спецификация механики возрождения уничтоженных группировок

Статус: **точка расширения реализована в К2**, полная механика — отдельная задача **К17** (предложение штабу).
Дата: 18.11.2026. Исполнитель: Qwen Code. Основание: правила B/C HQ (задача К2).

## 1. Что уже реализовано в К2 (обязательная база)

1. **Состояние уничтоженной группировки** — производное, без изменения формата сохранений:
   `Faction.isDestroyed() == !service && members <= 0`. Служебные фракции (Торговцы) не уничтожаются.
   Пустые фракции сценария (Малый Кордон: Долг, Свобода и др. с members=0) считаются уничтоженными
   с момента создания и могут быть возрождены в будущем.
2. **Фактические потери** — единая точка `Faction.killMembers(n)`: гибнет `min(n, members)`,
   `deaths` растёт ровно на фактическое число, `wounded <= members` всегда. Все боевые пути
   (война, набеги, засады, аномалии, выброс, мутанты, экспедиции, игровой слой) идут через неё.
3. **Событие уничтожения** регистрируется в журнале один раз (`destructionNoted`, не сохраняется;
   при загрузке восстанавливается из `members` — повторной регистрации нет).
4. **Запрет автоматического возрождения** (все пути перекрыты и проверены тестом):
   - новичок в пути не входит в уничтоженную фракцию (`People.join` — ищет другую или уходит);
   - паломники Монолита и призыв армии не пополняют фракцию с members=0 (`recruit`);
   - пробуждение Монолита не возвращает +42 уничтоженным (`activateMonolith`);
   - уничтоженный Монолит не занимает блокпосты (`monolithPosts`);
   - `applyCasualties/rout/overrun` не «воскрешают» отрицательными клампами;
   - уничтоженная фракция не принимает решений (`think`), не воюет (`resolveWars`), не торгует,
     не строит (`buildingsDaily`), не крафтит (`economy`), не имеет гарнизонов (`garrison`),
     не выполняет контракты (`npcResolve`), не раскалывается (`enclaves`).
5. **Точка расширения** — `Simulation.reviveByFreeStalkers(Faction f, int founders)`:
   - возрождать могут **только вольные сталкеры (Одиночки, `mercenaries()`)**: основатели
     физически переходят из Одиночков (`loners.members -= founders`), население Зоны сохраняется;
   - guards: фракция уничтожена, founders > 0, Одиночки живы и людей хватает; иначе `false`;
   - повторный вызов для живой фракции — `false` (без дублирования);
   - склад, касса и статистика (deaths, войны, захваты) уничтоженной фракции **не трогаются**:
     стартовые ресурсы повторно не начисляются, денежный баланс не обходится;
   - состояние сбрасывается: `phase=ACCUMULATE`, `phaseDays=0`, `wounded=0`;
   - именные и лидер восстанавливаются **штатным** `People.maintainRoster` на следующих шагах;
   - событие логируется («ВОЗРОЖДЕНИЕ: …»).
   Ежедневные циклы симуляции этот метод **не вызывают** — вызов только из игрового события (К17).

## 2. Полная механика (задача К17, решение штаба)

**Триггер (отдельное игровое событие, не незаметное изменение численности):**
- вариант A (квест игрока): игрок приводит группу сталкеров на базу уничтоженной фракции;
  игровой слой вызывает `reviveByFreeStalkers`; контракт/диалог — по дизайну штаба;
- вариант B (решение Одиночек): детерминированное событие в `UtilityBrain`/`People.daily`
  Одиночков: не чаще 1 раза в N дней, шанс p, только если Одиночки живы и сильны
  (`members >= порог`), цель — уничтоженная неслужебная фракция с сохранившейся базой.
  Вариант B требует отдельного решения штаба (это уже «автоматика», но инициированная
  вольными сталкерами как отдельное событие с журналом — соответствует правилу C).

**Параметры (предложение, утверждает штаб):**
- founders: 3–5 человек (не больше `loners.members / 4`, чтобы не обескровить инициатора);
- стоимость: 0 руб. (люди — единственный ресурс; деньги не чеканятся и не сжигаются);
  опционально взнос из кассы Одиночков возрождаемым через `Stock.moveMoney` (без Ledger);
- кулдаун на фракцию: не чаще 1 возрождения за 120 дней; на Одиночков: не чаще 1 за 60 дней;
- условие территории: база возрождаемой фракции должна быть свободна или принадлежать ей
  (историческое владение сохраняется за уничтоженной фракцией — узлы не отбираются
  автоматически при уничтожении, гарнизон = 0, узлы могут быть захвачены обычной войной).

**Восстановление связей:**
- участники: founders переходят из Одиночков; именные/лидер — штатный maintainRoster;
- территория: узлы, захваченные другими за время уничтожения, **не возвращаются** автоматически
  (возрождённая фракция отвёвывает их обычной войной/контрактами);
- дипломатия: `grudge`/`hostility` сохраняются (историческая память), перемирия не воскрешаются;
- фаза: ACCUMULATE; `unity` — предложить восстановление до 0.5 (решение штаба);
- статистика: deaths/nodesLost/caravansLost сохраняются как история; предложить счётчик
  `revivals` (если нужен — SAVE_VERSION+1 по конвенции: старые сохранения = 0, гейт Кордона).

**Запреты (проверять тестами К17):**
- никакого возрождения другими группировками и самовозрождения (все пути К2 остаются закрыты);
- никакого повторного начисления стартовых ресурсов и обхода денежного баланса;
- никакого дублирования фракции (id не меняется, объект тот же);
- детерминизм: один seeded rng на шаг, без Math.random;
- save/load: состояние производное от members — формат не меняется; новые поля (если появятся)
  гейтятся по конвенции SAVE_VERSION.

**Тесты К17 (предложение):** `FactionRevivalTest` — триггер, кулдауны, стоимость, территория,
дипломатия, save/load, соак с возрождениями (audit пуст ежедневно, население сохраняется:
сумма members по фракциям + transit + потоки People сходится с книгой населения К10).
