## Найденные и исправленные баги (ВАЖНО)

### **Зависание сервера при загрузке чанков** (три причины)

**Проблема:** сервер зависает (CPU 100%, не отвечает на RCON, не пишет в лог) при создании мира или загрузке области с постройками. Происходит при вызове `Level.setBlock` из `ChunkEvent.Load` или из `ServerChunkCache.getChunk` (генерация чанка).

**Три конкретные причины:**

1. **`onPlace`/`onRemove` пропсов лезли в соседний, ещё не готовый чанк.**
   - `ObjPropBlock` (декор построек: столбы, окна, ступеньки) при постановке (`onPlace`) или снятии (`onRemove`) проверял соседние блоки (для текстуры, связности).
   - Если сосед в чанке, который ещё не сгенерирован (или генерируется прямо сейчас), `Level.getBlockState(neighborPos)` вызывает генерацию этого чанка → рекурсия → зависание.

2. **Снимались блоки с BlockEntity.**
   - `Level.removeBlockEntity(pos)` при генерации чанка (например, убирали временный маркер или ошибочно поставленный сундук) → `Level.removeBlock` → может вызвать `onRemove` соседних блоков → см. пункт 1.

3. **Ставились жидкости.**
   - `Level.setBlock(pos, Blocks.WATER.defaultBlockState())` при генерации → `Level.scheduleTick` (жидкость течёт) → тик пытается обновить соседние блоки → см. пункт 1.

**Решение (реализовано в PR #116, 07.11.2026, журнал «Программиста»):**

- **Правило а4 (из решений):** «Постройки из тика `ServerLevel.tick`, не из генерации.» Блоки площадок ставятся не при `ChunkEvent.Load`, а из тика сервера (когда все чанки готовы).
- **Правило г7:** «Один такт отложить дорогое.» Постановка блоков откладывается на следующий тик после загрузки чанка.
- **Проверка `ObjPropBlock.worldgen`:** метод `worldgen()` возвращает `true`, если блок ставится при генерации мира (не из тика). В этом режиме `onPlace`/`onRemove` не трогают соседние блоки.
- **`Site.safeSet(level, pos, state)`:** обёртка над `Level.setBlock`, проверяет `level.isClientSide() || chunkSource.mainThreadProcessor.pendingTasksCount() == 0` (нет задач генерации в очереди). Если задачи есть — блок не ставится (отложится на следующий тик).

**Тест:** `ChunkLoadPlaceTest.java` — красный на коде до исправления (сервер зависает при попытке поставить блок при загрузке чанка), зелёный после.

**Проверено:** сервер облака с `.szl` пользователя (894 797 байт, мир TheZone) запускается за 37–46 секунд без зависания, все площадки (деревня, бункер, АТП, элеватор, заставы) на месте.

### **Прежние «серверные» проверки шли в обычном мире**

**Проблема:** в `server.properties` (облако) не был задан тип мира `level-type=stalkerzone:zone`. Сервер запускался с обычным миром Minecraft, симуляция не включалась, тесты проходили зелёными (но проверяли не то, что нужно).

**Решение:** в `tools/ci/server_smoke.sh` и конфиге облака добавлен `level-type=stalkerzone:zone`. Теперь сервер запускается в мире «Зона», симуляция работает, тесты проверяют реальное поведение.

---

### **У малых фракций залипала `matWant`**

**Проблема:** при загрузке сохранения у фракций с малым числом людей (≤10) переменная `matWant` (желание собирать материалы: дерево, железо, еда) не пересчитывалась, оставалась значением из сохранения. Из-за этого симуляция после загрузки шла иначе, чем при первом запуске (недетерминизм).

**Решение:** `Faction.load()` теперь всегда пересчитывает `matWant` после загрузки (как при создании новой фракции). Детерминизм восстановлен: результаты тестов баланса (хеши RNG) не изменились после правки.

## Зачем этот документ

Версия 1.14 — первая, которая **запускалась на сервере** (облако, RCON) и **не зависала при генерации мира**. Урок про три причины зависания (см. выше) **критически важен** для любой работы с постройками и генерацией:

- Если добавляешь новый блок с `onPlace`/`onRemove` — проверь, не лезет ли он в соседние чанки при генерации.
- Если ставишь блоки из события `ChunkEvent.Load` — используй `Site.safeSet`, не `Level.setBlock` напрямую.
- Если убираешь BlockEntity при генерации — отложи на следующий тик (`ServerLevel.scheduleTick`).

Актуальное состояние мода (18.11.2026) — `docs/claude/00-start-here.md`, roadmap — `docs/roadmap.md`. Этот документ — архив, но урок остаётся в силе.
