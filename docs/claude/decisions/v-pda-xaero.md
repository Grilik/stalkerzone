# Решение в) КПК на Xaero's World Map

**Статус:** черновик Opus (Э0-21, часть 1), 15.11.2026, с поправками штаба `docs/prompts/Э0-21-notes.md`. Проверка архитектором (Fable, вызов 2) обязательна: места помечены **[ПРОВЕРИТЬ]**, допущения — **[ДОПУЩЕНИЕ]**.
**Решения пользователя (не пересматриваются):**
- Xaero's Minimap — как есть.
- Xaero's World Map — **внутри КПК**: в выживании карта открывается по исследованию, в творческом видна целиком.
- Метки атласа (базы, заставы, торговцы) — точки на карте; их видимость зависит от знаний игрока.
- Версия локальная, чужие моды можно.

**Факты.**
- **Версии у игрока:** `xaerominimap-forge-1.20.1-26.6.0`, `xaeroworldmap-forge-1.20.1-1.47.0`, `xaeroplus-2.37.2forge-1.20.1-wm1.47.0-mm26.6.0`. Лицензия Xaero — All Rights Reserved: jar не кладём в репозиторий и не распаковываем в мод. Зависимость необязательная, как TaCZ.
- **В World Map 1.47.0** есть экран карты `xaero.map.gui.GuiMap` и система «элементов карты» `xaero.map.element.MapElementRenderHandler` / `MapElementRenderer` / `MapElementRenderProvider` — этим рисуются метки поверх карты.
- **В Minimap 26.6.0** — аналогичные `xaero.common.minimap.element.render.*` и путевые точки.
- **В XaeroPlus** есть `xaeroplus.feature.waypoint.WaypointAPI`.
- Стабильность этих классов как API не гарантирована автором. **[ПРОВЕРИТЬ]** Есть ли у 1.47.0 публичная регистрация своих рендереров элементов (аналог `MapElementRenderHandler.Builder` с внешними провайдерами), или она только внутренняя.
- **У мода сейчас:** КПК `client/PdaScreen` (5 вкладок, карта — граф узлов на подложке `PdaMapCache`), снимок `sim/PdaSnapshot` → `client/PdaModel`, сеть `Net` (канал «2»). Строки отрядов `Q` и населения `U` клиент пока отбрасывает (P-06, Э0-12).

## в1. Как КПК показывает карту Xaero

| Вариант | Суть | Плюсы | Минусы |
|---|---|---|---|
| 1. КПК открывает **экран `GuiMap` Xaero как есть** (кнопка «Карта» в КПК → `Minecraft.setScreen(new GuiMap(…))`), возврат в КПК по Esc | вызвать чужой экран | минимум кода; вся мощь Xaero (масштаб, слои, пещеры) | вид не «КПК», а Xaero; конструктор `GuiMap` — внутренний, может меняться между версиями |
| **2. КПК-рамка вокруг карты Xaero**: свой `PdaScreen` рисует рамку, вкладки и панели мода, а в окно карты встраивает `GuiMap` (дочерний экран, обрезка по области) | вид КПК, карта Xaero внутри | то, что попросил пользователь; вкладки мода (задания, контакты, группировки) рядом с картой | встраивание чужого `Screen` — отражение и обрезка (scissor); хрупко к версиям; тестируется только руками |
| 3. Своя карта мода по данным Xaero (читать тайлы карты Xaero с диска/кэша и рисовать самим) | не зависеть от экрана Xaero | полный контроль вида | дублирование большой работы Xaero; формат кэша закрыт; против «World Map внутри КПК как есть» |

**Выбор: вариант 2, с запасным 1.**
- Запуск через слой совместимости `compat/XaeroMap`, только отражение (как `compat/Tacz`):
  1. есть World Map нужной версии и встраивание удалось — рамка КПК с картой внутри;
  2. встраивание не удалось — кнопка открывает `GuiMap` целиком (вариант 1);
  3. Xaero нет — старая карта мода (граф узлов на подложке).
- Версия Xaero фиксируется в сборке (Э3-01). Обновление — только вместе с проверкой Э3-02.
- **[ПРОВЕРИТЬ]** Можно ли встроить `GuiMap` как дочерний виджет (рисовать в своём `render` с трансформацией), или проще наоборот: открыть `GuiMap`, а рамку и вкладки КПК рисовать поверх через событие рендера экрана Forge (`ScreenEvent.Render.Post` для `GuiMap`). Второй путь проще и надёжнее: Xaero сам обрабатывает мышь и масштаб, мод только дорисовывает рамку и боковую панель. **Рекомендация для Э3-02: начать с «поверх».**

## в2. Метки: базы, отряды, контракты

| Вариант | Суть | Плюсы | Минусы |
|---|---|---|---|
| 1. **Путевые точки Xaero** (waypoints): мод создаёт/обновляет точки в наборе «Зона» | штатный механизм, видны и на миникарте | просто; игрок может прятать набор | точки статичные (отряд в пути — частые обновления набора); вид точки ограничен (буква/цвет); игрок может их удалить; запись в файлы Xaero |
| **2. Свои элементы карты** через `ScreenEvent.Render.Post` поверх `GuiMap` (и при наличии — через `MapElementRenderHandler`) | мод рисует иконки, маршруты отрядов, подсказки сам, в координатах карты Xaero | любые иконки, линии маршрутов, анимация отрядов, тултипы; ничего не пишем в данные Xaero | нужно знать преобразование «блок → экран» текущего вида Xaero (масштаб, центр) — отражение |
| 3. Метки только в своей вкладке «Карта мода» | не трогать Xaero | надёжно | против решения «World Map внутри КПК» |

**Выбор: вариант 2 для динамики (отряды, маршруты, бой, рюкзак, контракты), вариант 1 — для статичных объектов, которые игрок открыл (базы, торговцы, заставы).** Это опция в настройках КПК, по умолчанию включена, набор путевых точек называется «Зона». Миникарта показывает только путевые точки из варианта 1. Динамику на миникарте не рисуем: Minimap — как есть.

- **Источник меток** — снимок КПК с сервера (`PdaSnapshot`).
  - Объекты атласа по ID (решение б): база, застава, торговец, логово, поле.
  - Отряды в пути (`Q`): позиция, цель, маршрут.
  - Контракты: цель и район.
  - Рюкзак смерти.
- **Видимость по знаниям.** Сервер отдаёт только то, что игрок знает:
  - открыл, побывав рядом;
  - купил у торговца, получил контрактом или от своей группировки.
  - Знания игрока — набор ID объектов атласа + время. **[ДОПУЩЕНИЕ]** Хранится в данных игрока (persisted NBT), как репутация. Клиент сам ничего не открывает.
- **Отряды** видны, только если их видел игрок или сообщили свои (рация, база). Позиция — на момент последнего сведения, с отметкой давности. Всеведения нет: мастер-спецификация, туман войны.
- **[ПРОВЕРИТЬ]** Как получить из `GuiMap` текущие центр и масштаб: поля через отражение или пересчёт по положению курсора. Это главный технический риск в2; разведка — первым шагом Э3-03.

## в3. Карта: в выживании по исследованию, в творческом целиком

| Вариант | Суть | Плюсы | Минусы |
|---|---|---|---|
| **1. Штатное поведение Xaero + предзаполнение для творческого** | Xaero сам строит карту по тому, что игрок видел (это и есть «по исследованию»); для творческого — заранее отрисованные тайлы всей карты TheZone кладутся в папку карты Xaero этого мира при создании мира | исследование «бесплатно»; творческий получает всю карту мгновенно | формат папки карты Xaero закрытый — предзаполнение копирует **готовую папку**, снятую один раз с прогретой золотой копии |
| 2. Творческий: временно включить в Xaero «режим без исследования» (если есть настройка/чит-режим) | настройка Xaero | без файлов | такой настройки может не быть; **[ПРОВЕРИТЬ]** |
| 3. Свой рендер всей карты в творческом | карта мода | контроль | против решения пользователя |

**Выбор: вариант 1.**
- Золотая копия мира (решение а3) поставляется вместе с **готовой папкой карты Xaero всей игровой зоны**: `xaero/world-map/<id мира>/…`. Её один раз снимает оператор, облетев прогретую золотую копию в творческом (или сервером с обходом). Снимок папки кладётся рядом с копией.
- Кнопка «Зона» (Э1-11) при создании мира:
  - режим «творческий» — копирует эту папку;
  - выживание — не копирует, карта строится исследованием.
- **[ПРОВЕРИТЬ]**
  - Как Xaero называет папку мира: по имени сохранения или по id — копирование должно попасть в нужное место.
  - Переключение режима в уже созданном мире (`/gamemode`) карту не дорисует. Это допустимо: решение про «творческий целиком» относится к созданию мира.

## в4. Без API: запасной путь
Каждая точка интеграции идёт через `compat/XaeroMap` с флагом `reflectFailed`, как TaCZ:
- не нашёлся класс или метод — пишется предупреждение в лог, мод работает;
- КПК откатывается на свою карту (граф узлов на подложке `PdaMapCache`) с теми же метками из снимка.

Тест `XaeroReflectTest` (чистый, по строкам) проверяет, что все имена классов и методов, которые ищет `compat/XaeroMap`, есть в jar версии из сборки. Jar берётся с ПК пользователя: в CI его нет, тест пропускается с пометкой, как с TaCZ (P-20).

**Риски.**
1. Обновление Xaero меняет внутренние классы — встраивание ломается. Защита: фиксированная версия, тест имён, запасной путь.
2. Лицензия ARR — jar Xaero не распространяем, игрок ставит сам; версия локальная, сейчас допустимо.
3. Производительность: перерисовка меток и маршрутов каждый кадр при сотнях отрядов. Защита: сервер шлёт только видимое игроку, лимит меток, отряды обновляются раз в 2–5 с с интерполяцией (как в `04-interfaces.md`).

**Как проверить (руками, в игре).**
- Выживание: КПК → «Карта» показывает карту Xaero в рамке КПК, открыто только пройденное; базы появляются после посещения, отряд — после встречи.
- Творческий в новом мире: видна вся игровая зона.
- Без World Map: КПК открывает свою карту, ошибок в логе нет.
- Обновление Xaero: тест имён падает до запуска игры.

## Задачи (строки `docs/roadmap.md`)
- **Э3-01** — версии Xaero (Minimap 26.6.0, World Map 1.47.0, XaeroPlus 2.37.2 — оставить или убрать XaeroPlus) в сборке, настройки по умолчанию, `XaeroReflectTest`.
- **Э3-02** — КПК открывает карту Xaero: рамка КПК **поверх** `GuiMap` (в1), вкладки мода, запасной путь.
- **Э3-03** — метки: свои элементы поверх карты (отряды, маршруты, контракты, рюкзак) + набор путевых точек «Зона» для открытых объектов; видимость по знаниям игрока. Зависит от Э0-12 (строки `Q`/`U` в `PdaModel`) и атласа (Э1-13 / Э2-05).
- **Э3-04** — творческий целиком: снимок папки карты Xaero с золотой копии, копирование кнопкой «Зона» (Э1-11).
- **Предложение Э3-08** — знания игрока: набор открытых объектов атласа в данных игрока, источники знаний (посещение, торговец, контракт, своя группировка), отдача в снимок КПК. Чистое ядро + тест (карточка конвейера).

## Вопросы пользователю
1. **XaeroPlus** оставляем? Он меняет поведение карты (и тянет свои миксины). Для «по исследованию» он не нужен. Допущение: убрать из сборки игры, если встраивание с ним ломается.
2. **Путевые точки «Зона» на миникарте:** показывать открытые базы и торговцев? Допущение: да, отключаемо в КПК.
