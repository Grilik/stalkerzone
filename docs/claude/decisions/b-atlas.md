# Решение б) Атлас Зоны

**Статус:** черновик Opus (Э0-21, часть 1), 15.11.2026, с поправками штаба `docs/prompts/Э0-21-notes.md`. Проверка архитектором (Fable, вызов 2) обязательна: места помечены **[ПРОВЕРИТЬ]**, допущения — **[ДОПУЩЕНИЕ]**.
**Основа:** решение а) (`a-world-thezone.md`), мастер-спецификация §4 (атлас как данные со статусами), находки Э1-01 (`docs/thezone/places.json` — 19 локаций по телепортам автора, `docs/thezone/img/overview.png`), метод Кордона `tools/xray/kordon_points.py` → `src/main/resources/data/stalkerzone/points/l01_escape.json`, симуляция (`KordonScenario.COORDS`, `ZoneScenario`, `Prefabs.NODE_*`).

**Факты.**
- Сейчас «атлас» — это файл одного уровня `points/l01_escape.json`: `shift`, `bounds`, `spawn`, `exits`, `closedPassages`, `nodes[]` (`id`, `name`, `center`, `campfire`, `beds`, `guards`, `flag`, `patrol`, `shelter`, `anomalySmart`), `roads`.
- Точки сняты `kordon_points.py` из смарт-террейнов Anomaly: `kamp_*` — костры, `sleep_*` — места сна, `guard/grd/sniper_*` — часовые, `comander_*` — флаг, `walker/pat` — патруль, `esc_m_trader` — торговец, `level_changer` — переходы. Переведены в координаты Minecraft одним сдвигом уровня: x = xr_x + DX, z = −xr_z + DZ, y = xr_y + YOFF.
- Номера узлов Кордона продублированы в шести местах (P-15 аудита): `KordonScenario.COORDS`, `Prefabs.NODE_*`, `NodePopulation`, `ContractBoard`, `KordonBalance`, JSON.
- TheZone — авторская карта. Взаимное положение и масштаб локаций не совпадают с глобальной картой ТЧ, поэтому один сдвиг на весь мир не подходит.

## б1. Формат атласа

| Вариант | Суть | Плюсы | Минусы |
|---|---|---|---|
| 1. Расширить `points/<уровень>.json` | по файлу на уровень, как сейчас | ничего не ломаем | нет мира целиком (граница, переходы между локациями, графы дорог); ID только числом |
| 2. База данных (SQLite) | таблицы объектов и связей | запросы | бинарник в git, не читается глазами, сложнее тестам на чистом javac |
| **3. Атлас — папка JSON, по файлу на локацию + файл мира** | `data/stalkerzone/atlas/world.json` + `atlas/locations/<loc>.json`; стабильные строковые ID; схема `atlas.schema.json`; валидатор — чистый тест | читается глазами и диффом; локации правятся независимо (меньше конфликтов PR); тот же формат читают Python-инструменты и мод | нужен загрузчик и миграция с `l01_escape.json` |

**Выбор: вариант 3.**

**`world.json`:**
- `version`, `base: "thezone"`, `bounds` — многоугольник по западной трети мира. ЧАЭС, генераторы и Дуга внутри, южная полоса и восток снаружи (ответы пользователя 15.11).
- `spawn`, `locations[]` (id → файл), `links[]` — дороги и переходы **между** локациями.

**`locations/<loc>.json`:**
- `id` (`cordon`, `garbage`, `agroprom`…), `name`, `bbox`, `teleport` (точка из `places.json`), `source` (уровень оригинала, например `l01_escape` Anomaly / CoC).
- `transform` (б2), `anchors[]`, `residual`.
- `objects[]` — объекты локации.

**Объект:**
- `id` — `<loc>.<kind>.<имя>`, например `cordon.base.village`, `cordon.outpost.o7`, `cordon.field.a6`, `cordon.lair.l3`.
- `kind` — одно из: `base`, `outpost`, `checkpoint`, `field` (аномальное поле), `lair`, `cache` (тайник), `trader`, `exit`, `landmark`, `road_node`.
- `owner` — стартовая группировка; `node` — номер узла симуляции, если объект — узел (б3).
- `pos`, `bbox`, `points` — `campfire`, `beds`, `guards`, `patrol`, `shelter`, `flag`, `trader`, `kill_line`, `mg`… (те же виды, что в `l01_escape.json` и метках сборщиков).
- `site` — площадка: сборщик, режим `keep` / `adapt` / `redesign` (решение а4), уровень.
- `status` — `observed` / `accepted` / `redesign` / `new` / `built` / `verified` / `integrated` (мастер-спецификация §4).
- `source` — откуда взято: смарт-террейн Anomaly, съёмка Э1-04, ручная правка с датой.

**Дороги:**
- `roads[]` в локации — полилинии с `surface` (асфальт, грунтовка, тропа, ж/д) и `passable` (для NPC и караванов).
- Между локациями — `world.links[]` (`from`, `to`, полилиния, тип).

**[ДОПУЩЕНИЕ]** Атлас лежит в ресурсах мода (`src/main/resources/data/stalkerzone/atlas/`) и едет вместе с модом. В нём только координаты Minecraft и типы, данных игры GSC нет: так же, как `kordon_points.py` пишет только координаты. Правило `CLAUDE.md` о данных GSC не нарушается.
**[ПРОВЕРИТЬ]** Должен ли атлас лежать ещё и в папке мира (`stalkerzone/atlas/`) вместе с золотой копией, чтобы мир и атлас не разошлись. Предложение: в мире хранится только `atlasVersion` в манифесте (решение а1), при несовпадении — предупреждение в лог.

## б2. Перенос разметки уровня на TheZone

| Вариант | Суть | Плюсы | Минусы |
|---|---|---|---|
| 1. Один сдвиг на весь мир | как Кордон 1:1 | просто | TheZone — авторская карта, масштаб и взаимное положение локаций свои — не подходит |
| **2. Преобразование по локации по опорным точкам (якорям)** | для каждой локации — подобие (сдвиг + поворот + один масштаб) по ≥ 3 якорям методом наименьших квадратов; невязка по каждому якорю и средняя | одна формула на локацию, проверяемая; невязка показывает, где автор TheZone отошёл от оригинала | нужны якоря — объекты, которые есть и в уровне, и в TheZone |
| 3. Ручная расстановка каждой точки | глазами по TheZone | точно для каждой точки | сотни точек, не воспроизводимо, нельзя пересчитать при смене разметки |

**Выбор: вариант 2.** Подобие, а не аффинное преобразование: аффинное «растягивает» локацию по одной оси и скрывает ошибки. Если у локации невязка подобия велика, это не повод подгонять формулу, а сигнал: автор TheZone перестроил локацию.

- **Якоря.** Объекты, узнаваемые в обоих мирах: перекрёстки дорог, мосты, углы крупных зданий, вышки, ж/д переезды.
  - Кандидатов предлагает инструмент: по съёмке Э1-04 и по уровню оригинала.
  - **Подтверждает пользователь по F3:** стоит на месте в TheZone, пишет координаты.
  - В `anchors[]` — пары `{original: [x,z], thezone: [x,y,z], label, confirmedBy, date}`.
- **Невязка.** Для каждого якоря — расстояние после преобразования; `residual.rms` и `residual.max` пишутся в файл локации. Пороги:
  - rms ≤ 8 блоков и max ≤ 16 — преобразование принято;
  - иначе локация делится на части (например, Припять — север/юг/центр/восток/запад уже разделены автором в `places.json`), у каждой своё преобразование;
  - если и так не сходится — точки ставятся вручную со статусом `observed`.
  - **[ПРОВЕРИТЬ]** Пороги 8/16 — допущение; уточнить на Кордоне (Э1-06).
- **Высота.** Y не переносится из оригинала: берётся из живых чанков TheZone по правилу «земля» (решение а5) при утверждении точки. Точка в воздухе или под землёй больше чем на 2 блока — флаг в отчёте валидатора.
- **Проверка по местности (Э1-07).** Каждую перенесённую точку проверяет валидатор:
  - не в стене постройки;
  - не в воде (кроме переправ);
  - укрытие `shelter` — под крышей;
  - костёр — на ровном.
  - По итогу формируется отчёт по локации. Пользователь утверждает локацию целиком (статус `accepted`).
- **Инструмент.** Расширение `tools/xray/kordon_points.py` до `tools/atlas/import_level.py <level> <loc>`: читает смарт-террейны уровня, применяет преобразование локации, пишет `objects[]` со статусом `observed`. Повторный запуск не трогает объекты со статусом выше `observed`.
- Порядок по локациям: сначала Кордон (Э1-06/07, Э2), остальные — Э5.

**[ДОПУЩЕНИЕ]** Источник разметки для локаций, которых нет в ТЧ, но есть в TheZone (Затон, Янов, Лиманск, Мёртвый город, Болота), — уровни Call of Chernobyl / Anomaly. Для Затона и Янова в Anomaly есть уровни ЗП (`zaton`, `jupiter`). Пользователь подтверждает, какая версия уровня — источник.

## б3. Единый реестр узлов симуляции из атласа

| Вариант | Суть | Плюсы | Минусы |
|---|---|---|---|
| 1. Оставить номера в коде (`COORDS`, `NODE_*`) + тест согласованности (Э0-11) | как сейчас | минимум работы | шесть копий остаются; новые локации Э5 умножают их |
| **2. Узлы из атласа**: объект атласа с полем `node` и есть узел; `KordonScenario`/`ZoneScenario` берут список, координаты, тип и владельца из атласа; номера `node` — постоянные, только дописываются в конец | одна правда о «где узел»; новая локация = новые объекты атласа | загрузчик атласа должен быть в чистом ядре (`sim`/`zonemap` без Minecraft) — тестам и конвейеру |
| 3. Строковые ID вместо номеров узлов везде | `cordon.base.village` вместо 0 | читаемо | меняет сохранения (номера в `Simulation.save`), карточки, тесты — большой риск сейчас |

**Выбор: вариант 2.**
- Номер узла остаётся числом в сохранении, атлас — единственный источник соответствия «номер ↔ объект ↔ координаты».
- Строковый ID — для людей, документов и меток КПК.
- Кодек со стабильными ID (Э4-05) позже может перейти на строки.
- Э0-11 (тест согласованности) остаётся полезен как переходный шаг: он ловит расхождение кода и JSON, пока часть констант живёт в коде.

**Правила.**
- Загрузчик атласа — чистая Java в `zonemap/atlas/*` (без Minecraft, читает JSON без библиотек, как `LevelPoints`). Его же читают тесты.
- Номер `node` назначается при первом появлении объекта и никогда не меняется. Удалённый объект оставляет «дыру» со статусом `removed`, номер не переиспользуется.
- Сценарий описывает поведение (доктрины, баланс), а не геометрию. Геометрия — только из атласа.
- Координаты узла в симуляции (`Node.x/z` в единицах ×10) вычисляются из атласа при создании симуляции. **[ПРОВЕРИТЬ]** Не потеряется ли точность графа дорог `ZoneGraph`: длина рёбер считается по координатам узлов.

## б4. Валидатор атласа (тест для CI и конвейера)
`AtlasTest` на чистом javac проверяет:
- ID уникальны;
- `node` уникальны и не переиспользованы;
- все `links` ведут к существующим локациям;
- объекты внутри `bbox` локации и внутри `world.bounds` (кроме `exit`);
- `CLEAR` площадок не пересекаются;
- у каждой базы есть `campfire` и `beds`;
- `residual` записана и в пределах порога либо у объектов статус `observed`;
- `teleport` из `places.json` внутри `bbox` своей локации.

Падающий тест для карточки конвейера: «атлас Кордона загружается, узлы 0–23 совпадают с `KordonScenario.COORDS` ±1 блок» — до перевода Кордона на атлас (Э2-05).

**Риски.**
1. Пользователь не найдёт якорей (локация перестроена автором TheZone до неузнаваемости). Тогда точки ставятся вручную по съёмке, статус `observed`, без формулы.
2. Атлас и золотая копия мира разойдутся: постройка сдвинута, точка осталась. Против этого: `atlasVersion` в манифесте и пересчёт точек площадок при каждой постановке (решение а4 пишет `id` объекта атласа в журнал).
3. Большой файл Припяти конфликтует в PR. Против этого — деление по частям, как у автора.

**Как проверить.**
- Кордон: ≥ 4 якоря от пользователя, rms ≤ 8.
- Все 19 узлов из `l01_escape.json` перенесены, валидатор зелёный.
- 10 случайных точек пользователь находит по F3 на месте: костёр у костра, часовой у вышки.
- `KordonScenario` строится из атласа, все тесты симуляции зелёные.
