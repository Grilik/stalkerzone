# Решение а) Мир на TheZone

**Статус:** черновик Opus (Э0-21, часть 1), 15.11.2026. **Проверка архитектором (Fable) после 19.11 обязательна** — места помечены **[ПРОВЕРИТЬ]**, допущения — **[ДОПУЩЕНИЕ]**.
**Основа:** решения пользователя 15.11 (`docs/roadmap.md`), мастер-спецификация §4–5, `LivingZone_Documentation/06_NEW_DOCUMENTATION/2026-11-14_thezone-integration-options.md` (вариант А принят пользователем, Кордон 1:1 из `.szl` заморожен), план этапа 0 (`agent-team-audit/10-phase-0-execution-plan.md` §3 — зависания при загрузке чанков, D3 — сброс сохранения), код `main` 8721aac.

**Факты, от которых зависит решение** (проба 14.11 + проверка 15.11, только чтение): TheZone — Java 1.20.1 (DataVersion 3465), 491 регион ≈ 462 000 чанков, все `full`; прямоугольник x −6656…6143 × z −4608…4607 плюс полоса в один регион на юг (x 3584…4095, z до ≈ 8703); генератор в `level.dat` ванильный, seed −840995054016536013, спавн (0, 15, 0); в чанках **нет** `Heightmaps` и `blending_data`; в папке мира только `level.dat`, `region/` (1,8 ГБ), `entities/` (нет `data/`, `poi/`, других измерений). Готовые чанки игра никогда не генерирует заново; биомы хранятся в чанках — `ZoneBiomeSource` на TheZone не действует.

Сейчас мод пишет блоки в мир тремя путями: генерация (`XrayPlacer`, `PrefabLayer` из `.szl` и `Site`), `ChunkEvent.Load` (`WallBuilder` по `ZoneBounds`, декор и лагеря `StructureManager`/`ZoneMapPlacer`, всё через `ObjPropBlock.safeSet`), команды (`/zone rebuild`). На TheZone первый путь отпадает сам (чанки готовы), второй — источник всех зависаний 31.10–07.11.

## а1. Режим мира «без генерации внутри TheZone»

| Вариант | Суть | Плюсы | Минусы |
|---|---|---|---|
| 1. Ванильный генератор в `level.dat`, мод «не знает», что это TheZone | ничего не меняем | ноль работы | за краем генерируется обычный Minecraft (видно из-за забора); хуки `ChunkEvent.Load` мода работают по координатам Кордона 1:1 — лагеря и стена встанут не туда; режим не проверяем |
| 2. Пресет мода `stalkerzone:zone` в `level.dat` | новые чанки за краем — рельеф Зоны | бесшовное расширение | нужен «подъём к краю» в `XrayTerrain` (нет); генератор тянет `.szl`-логику, вредную на TheZone; швы |
| **3. Явный режим `THEZONE` по манифесту мира + свой пресет для пустых чанков** | в папке мира файл `stalkerzone/world.json` (`{"base":"thezone","goldenVersion":…,"atlasVersion":…,"simSeed":…}`); при нём мод в режиме `THEZONE`: **никаких записей блоков при генерации и при `ChunkEvent.Load`**, координаты площадок, узлов и границы — из атласа (решение б); отсутствующие чанки за краем — плоская «пустошь» на краевой высоте (пресет `stalkerzone:thezone_edge`: `minecraft:flat`, биом `stalkerzone:perimeter`) | режим проверяем (файл есть/нет); старые миры и CI на `fake_szl` не ломаются; главный класс зависаний закрыт на корню — при загрузке чанка мод не пишет ничего | надо пройти все хуки генерации и `ChunkEvent.Load` и поставить проверку режима; шов «рельеф TheZone → плоскость» (за границей, игрок туда не попадает) |

**Выбор: вариант 3.** Причина: решение пользователя «основа — TheZone, импорт `.szl` заморожен» плюс урок этапа 0 — лучшая защита от зависаний при загрузке чанка не «безопасная запись», а **отсутствие записи**. Всё, что мод ставит в TheZone, ставится один раз инструментом постановки (а4) в рабочую копию, до раздачи игроку. Манифест, а не признак из `level.dat` — потому что пресет за краем может смениться, а признак режима должен быть один и явный.

- **[ДОПУЩЕНИЕ]** Манифест — JSON в `stalkerzone/world.json` папки мира, читается на `ServerAboutToStartEvent` (`LevelResource.ROOT`); не SavedData — его пишет скрипт без Minecraft.
- **[ДОПУЩЕНИЕ]** Сценарий симуляции в режиме `THEZONE` — пока `kordon` с координатами из атласа (Э2); `zone` (вся Зона) — после атласа всех локаций (Э5). Системное свойство `stalkerzone.scenario` остаётся для тестов.
- **[ПРОВЕРИТЬ]** Полный список мест, которые пишут блоки вне команд (`ChunkEvent.Load`, `PrefabLayer`, `XrayPlacer`, `StructureManager`, `WallBuilder`, `Camp`, `WorldDecorator`, `RadioactiveSpots`, `Landmarks`, `LandmarkManager`, `BridgePost`, `Painter`) — составляет исполнитель Э1-09, архитектор сверяет.
- **[ПРОВЕРИТЬ]** Как Forge/игра реагируют на смену генератора в `level.dat` готового мира (окно «экспериментальные настройки»), и не нужен ли вместо смены пресета просто `flat`-генератор ванили.

**Риски.** (1) Забытый хук пишет блоки на TheZone — ловится тестом-сканером (расширение `ChunkLoadPlaceTest`: каждый путь записи при загрузке чанка начинается с проверки режима) и счётчиком подмен Э0-08 (должен быть 0, а в режиме `THEZONE` — и число записей 0). (2) Логика, завязанная на биомы мода (`WorldDecorator`, погода, цвета, спавн мутантов по биому), на TheZone не сработает; источник «где я» в режиме `THEZONE` — локация атласа, а не биом.
**Как проверить.** Сервер на копии TheZone с манифестом: 30 мин обхода Кордона (игрок или `forceload`-обход в CI-сессии), в логе `substitutions=0` и `chunkWrites=0`; сравнение `region/*.mca` до/после по секциям блоков (скрипт Э1-08) — блоки не изменились.

## а2. Край мира

| Вариант | Суть | Плюсы | Минусы |
|---|---|---|---|
| 1. Только ванильный `WorldBorder` | квадрат | готов | TheZone — прямоугольник 12,8 × 9,2 км: квадрат либо режет мир, либо оставляет полосы пустых чанков |
| 2. Забор + барьер `WallBuilder` при загрузке чанка (как сейчас) | | облик есть | запись при загрузке чанка — то, что запрещаем в а1; массивный забор пользователь просил заменить (R-WLD-07) |
| **3. Граница — часть мира, ставится один раз + периметр без блоков** | контур края — из съёмки (Э1-04) в атлас (`world.bounds`); колючая проволока / плавный край по камням ставится **инструментом постановки** (а4) как обычная постройка (Э2-10); в рантайме `Perimeter` только возвращает игрока внутрь контура; ванильный `WorldBorder` — запасной квадрат, охватывающий весь прямоугольник | ничего не пишется при загрузке; облик — по желанию пользователя; край двигается вместе с атласом | граница ≈ 44 км — большая постановка, по частям; судьба южной полосы |

**Выбор: вариант 3.** Граница внутри TheZone с отступом 1–2 чанка от края данных, чтобы игрок не видел пустошь вплотную; полоса между границей и краем — буфер без построек.
- **[ДОПУЩЕНИЕ]** Южная полоса (x 3584…4095, z 4608…8703) — вне игровой зоны до решения пользователя (вопрос 1).
- **[ДОПУЩЕНИЕ]** В Э1–Э2 игровая зона может быть меньше всего мира (только Кордон и соседи) — граница Э2-10 ставится по контуру «открытой части» из атласа, внешний край — позже.
- **[ПРОВЕРИТЬ]** `ZoneBounds` сейчас — прямоугольник из узлов × 10 + 300; нужен прямоугольник/многоугольник из атласа. Минимально — прямоугольник; многоугольник — если съёмка покажет неровный край.

**Как проверить.** `/zone tp` в 8 точек края: проволока стоит, за ней буфер; попытка выйти — возврат; `WorldBorder` изнутри не виден.

## а3. «Новый мир = копия TheZone», `ZoneData` и сброс симуляции

Minecraft Java не умеет «создать мир из шаблона». Три пути:

| Вариант | Суть | Плюсы | Минусы |
|---|---|---|---|
| **1. Скрипт** `tools/thezone/new_world.ps1 <имя>` | копирует «золотую копию» в `saves/<имя>` (или в папку сервера), пишет манифест с новым `simSeed`, проверяет, что `data/stalkerzone_sim.dat` нет | просто, проверяемо, работает и для сервера в облаке | шаг вне игры |
| 2. Мод копирует шаблон при создании мира | тип мира «Зона (TheZone)» в меню, мод на `ServerAboutToStart` копирует регионы из `stalkerzone/template/` | удобно игроку | регионы надо положить до подготовки спавна; хрупко; шаблон 1,8 ГБ в папке игры |
| 3. Раздавать архив мира | игрок распаковывает сам | ноль кода | ошибки игрока, один `simSeed` у всех |

**Выбор: 1 сейчас, 2 — отдельной задачей перед 1.0 (Э12), если пользователь захочет кнопку.** Раздача («готовый мир + мод») = архив золотой копии + скрипт; в git — только скрипт.

**Золотая копия** — не исходный TheZone, а результат конвейера: `оригинал (неизменный) → рабочая копия (Э1-03) → прогрев → постановки (а4) → проверка → золотая копия vN`. Прогрев — один проход сервера по всем чанкам: игра сама досчитывает отсутствующие `Heightmaps` и свет, долгая первая загрузка не достаётся игроку. **[ПРОВЕРИТЬ]** Чем прогревать: свой обход `forceload` в серверной сессии или мод Chunky (обходит ли он существующие чанки или только генерирует отсутствующие — проверить на копии); время прогрева 462 000 чанков.

**`ZoneData` и сброс.** Сейчас `ZoneData` (`stalkerzone_sim.dat`) хранит вместе симуляцию и «что построено в мире» (`built`, `campY`, `rendered`, `hidden`, `life`, `tick`), а Э0-14b при смене версии сохранения очищает всё это. На TheZone так нельзя: постройки уже **в чанках** золотой копии; если сброс забудет `built`, а код по `built` решает «строить ли лагерь», лагерь встанет второй раз. Решение:
- В режиме `THEZONE` «что построено» хранится **не в `ZoneData`, а в журнале постановок** мира `stalkerzone/placements.jsonl` (пишет только инструмент а4). `built`/`campY`/`rendered` в этом режиме не используются — на них не ветвится ни один путь постановки (проверяет тест Э1-09).
- Сброс симуляции (D3, Э0-14) в режиме `THEZONE` пересоздаёт `Simulation`, `ZoneLife`, `hidden`, `tick`; журнал постановок и чанки не трогает.
- Сид симуляции — `simSeed` из манифеста (новый у каждой копии), а не сид мира: сид мира у всех копий TheZone один (`ZoneData.get` сейчас берёт `server.overworld().getSeed()`).
- Новая версия сохранения (смена набора узлов) = новая симуляция; на TheZone это **не** требует нового мира, если постройки не менялись. Смена построек = новая золотая копия.

**Риски.** «Журнал говорит построено — в чанках нет» после ручного отката регионов → откат только инструментом а4, который правит журнал. **Как проверить.** Два мира из скрипта: разные `simSeed`, через 3 игровых дня разное состояние; подмена версии в `stalkerzone_sim.dat` → сообщение Э0-14b, постройки на месте, вторых лагерей нет.

## а4. Инструмент постановки сборщиков в готовый мир

| Вариант | Суть | Плюсы | Минусы |
|---|---|---|---|
| 1. Правка `.mca` офлайн (Python/Amulet) | писать секции напрямую | без Minecraft, быстро | спецификация запрещает «править `.mca` без проверенной процедуры»; свет, карты высот, BlockEntity, NBT `FramedBlocks` — вручную; сборщики на Java (`BlockSink`) пришлось бы дублировать |
| 2. Команда в игре `/zone place <site>` | живой сервер, игрок рядом | тот же код, что в игре | зависит от загруженных чанков и места игрока; не повторяемо |
| **3. Серверная сессия постановки** на рабочей копии: `-Dstalkerzone.place=<site,…>` | после `ServerStartedEvent`: копия затронутых `r.x.z.mca` в `backup/<время>-<site>/` → билеты `forceload` на прямоугольник площадки + 1 чанк вокруг → **ждать, пока все чанки FULL** (без записи) → высоты (а5) → сборщик через `ZoneMapPlacer.LevelSink` частями (≤ N блоков за тик) → второй проход форм → строка в журнал → `save-all flush` → снять билеты → выход | повторяемо как `server_smoke.sh`; работает на облачном сервере и в CI; существующие сборщики `zonemap/build/*` без изменений; ни одной записи внутри `ChunkEvent.Load` | ещё один режим запуска; вся граница и все площадки — минуты-часы |

**Выбор: 3.** `/zone place` — тонкая обёртка над тем же кодом, для оператора (права 2, флаг `-Dstalkerzone.ci=true`, как dev-команды Э0-07).
**Уроки зависаний, зашитые в инструмент:** запись только из тика сервера и только когда вся площадь **и её соседи (+1 чанк)** загружены — `onPlace`, `setChanged`, формы заборов не ждут чанк; бюджет блоков на тик; `ServerWatchdog` активен; высоты читаются только через `hasChunk`; постановка запрещена, пока идёт `ChunkEvent.Load` (флаг `ObjPropBlock.PLACING`).
**Журнал** `stalkerzone/placements.jsonl`, строка на постановку: `id` объекта атласа, сборщик и уровень, git sha, прямоугольник, высота плато и откуда взята, регионы и путь резерва, счётчик подмен, время. **Откат** `--undo <id>` — возврат регионов из резерва, только если после этой постановки те же регионы никто не менял (иначе отказ с перечнем); строка «отменено» в журнал. Повторная постановка того же `id` без `--force` — отказ.

- **[ДОПУЩЕНИЕ]** `Site.plateau` на TheZone работает как на `.szl`: плато + откос режут рельеф только внутри прямоугольника; высота — из живых чанков (а5); `CLEAR` сносит постройки TheZone внутри.
- **[ПРОВЕРИТЬ]** Сносить ли постройки TheZone внутри площадки или вписывать сборщик в них — решается по каждой площадке в атласе (статус `redesign`/`new`), не в инструменте.
- **[ПРОВЕРИТЬ]** Сущности TheZone (`entities/`) в прямоугольнике — удалять или оставлять.

**Риски.** Повреждение регионов — резерв до записи с контрольными суммами; постановка поверх соседней площадки — валидатор атласа (решение б) проверяет пересечения `CLEAR`. **Как проверить.** Постановка деревни на копию: `substitutions=0`, сторож молчит, TPS ≥ 19; откат → регионы побайтно равны резерву; повтор → отказ без `--force`.

## а5. Высоты площадок из живых чанков

| Вариант | Суть | Плюсы | Минусы |
|---|---|---|---|
| 1. Только живая карта высот при постановке | `Heightmap.Types.WORLD_SURFACE` | точно то, что в мире | карт высот нет до прогрева; «поверхность» = крыши и кроны; нельзя спланировать заранее |
| 2. Только офлайн-растр из регионов | Python по `region/*.mca` (`tools/xray/mca.py` уже читает), «земля» = верхний блок из списка грунтов | планирование, превью, проверки без мира | может разойтись с живым миром после правок |
| **3. Растр для плана + сверка при постановке** | растр `ground` из съёмки Э1-04 — для атласа, превью, валидатора уклонов; при постановке — медиана «земли» по живым чанкам тем же правилом; расхождение с растром > 2 блоков — отказ с отчётом | план и мир сверяются, а не подменяют друг друга | правило «что считать землёй» в Python и Java — нужен общий список блоков |

**Выбор: 3.** «Земля» — верхний блок из списка грунтов (`grass_block`, `dirt`, `coarse_dirt`, `podzol`, `gravel`, `sand`, `stone`… — уточняется по таблице материалов Э1-02 `docs/thezone/02-materials.md`), без бревён, листвы и блоков построек; вода — отдельный слой, как в `.szl`. Список — один файл данных `data/stalkerzone/thezone/ground_blocks.json`, его читают и съёмка, и `Site` (адаптер чтения живого мира).
- **[ДОПУЩЕНИЕ]** Медиана — как у `Site.AUTO`; площадки на склоне — плато + откос, как на Кордоне 1:1.
- **[ПРОВЕРИТЬ]** Растр вне git (≈ 12 800 × 9 216 × 2 байта ≈ 235 МБ сырьём); в git — скрипт и, если нужно тестам, срезы по площадкам.

**Как проверить.** Для 5 площадок Кордона: высота из растра, из живых чанков и в игре совпадают ±1; лог постановки содержит обе.

## Задачи (строки `docs/roadmap.md`)
- **Э1-03** — резерв, рабочая копия, журнал правок мира, откат (основа а3–а4).
- **Э1-04** — съёмка, растр `ground`, список грунтов (а5), контур края (а2).
- **Э1-08** — опытная копия: прогрев, первый запуск с модом, TPS, сравнение регионов до/после обхода.
- **Э1-09** — режим `THEZONE` по манифесту: нет записи при генерации и загрузке чанка, пресет за краем, `built`/`campY`/`rendered` не используются (а1, а3).
- **Э1-11** (новая) — «новый мир = копия»: золотая копия vN, `new_world.ps1`, `simSeed` из манифеста, сброс симуляции без потери построек (а3).
- **Э2-01** — серверная сессия постановки с журналом и откатом (а4, а5).
- **Э2-10** — граница постановкой, `Perimeter` без блоков, запасной `WorldBorder` (а2).
- **Связь с Э0-14b:** Э0-14b делается для старого режима как в плане этапа 0; ветку `THEZONE` (сброс не трогает журнал постановок) добавляют Э1-09/Э1-11. **[ПРОВЕРИТЬ]** не проще ли сразу сделать Э0-14b с учётом режима.
