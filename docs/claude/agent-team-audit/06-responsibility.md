## 3. Предложения (на решение пользователя)

| № | Предложение | Зачем | Кто исполняет |
|---|---|---|---|
| 3.1 | **Источник правды — репозиторий.** `docs/claude/` считать главным всегда; Project на claude.ai — зеркало. Штаб пишет `00/01/02` через PR (или присылает текст, который рабочий чат кладёт в PR вместе с задачей). | Закрывает 2.1–2.2: один источник, история в git, новый Claude по `CLAUDE.md` видит актуальное | пользователь решает; Программист — первый PR синхронизации (см. `07-roadmap.md`, этап 0) |
| 3.2 | **Правило «коммит = запись»**: PR, меняющий поведение, обязан менять либо журнал роли (`10`/`11`), либо карточку (`docs/tasks`), либо чек-лист (`docs/checklist`). Проверять в ревью, не в CI. | Закрывает 2.3 | Программист, Строитель |
| 3.3 | **Конвейер = исполнитель любой карточки с красным тестом**, включая ядро симуляции; запрет остаётся на облик, клиентские экраны, `.github/workflows`, `world/*` при загрузке чанков (там тест не ловит зависание). Переписать п. 1–2 в `06-conveyor-v2.md` и `.clinerules`. | Узаконить практику 2.5, при этом не пускать конвейер туда, где ошибка проявляется только на сервере | штаб (документ), Программист (`.clinerules`) |
