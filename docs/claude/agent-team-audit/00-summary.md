## Главный вывод
Ядро проекта здоровое: чистая симуляция без Minecraft с 78 тестами (все зелёные в Linux CI; на Windows 77 из 78, `FramedTest` красный из-за CRLF), детерминизм и закон сохранения проверяются, симуляция не нагружает тик (шаг дня около 1 мс), конвейер v2 дёшев (23 PR, ≈ $0,46). Проблемы — не в коде ядра, а в **швах**: между документами и кодом, между симуляцией и миром, между «карточка зелёная» и «видно в игре», между CI и релизом. Именно там за последнюю неделю произошло всё, что мешало играть: три зависания при загрузке чанков, ложные ограничения в промптах, экраны, для которых данные уже считаются, но не показываются.

## Пять критичных проблем (подробно — `05-problems-and-risks.md`, раздел A)
1. **Документы точки входа описывают не тот проект.** `00-start-here.md`, `01-malyi-kordon.md` и промпт «Программист» отстали на 32 PR: там «военные и бандиты выключены», в коде — гарнизоны на блокпосте и АТП; там «АТП/элеватор/туннель отключены», в коде — 9 площадок. Новый чат по `CLAUDE.md` получит ложную постановку. (P-01)
2. **Нет единственного источника правды.** Штаб — в Project вне репозитория, решения пользователя оседают в журнале Программиста, сверка `docs/claude` не выполняется с 06.11. (P-02)
3. **Зависание при загрузке чанка — класс ошибок с общим корнем** (декор уровня на серверном потоке в `ChunkEvent.Load`), три исправления за три дня 05–07.11, первое зависание у игрока — 31.10; остались обходы `safeSet`, срабатывание которых не доказано (`WallBuilder.java:42` и две ветки `ObjPropBlock`). Плейтест после #117 не подтверждён. (P-03)
4. **Инструкция по тестам на Windows не работает**: `simtest.ps1` не компилируется, `FramedTest` красный из-за CRLF, три копии списка исходников расходятся. (P-04)
5. **Релиз `nightly` выходит без проверки сервера**: задание `server` не в `needs`, на `main` отменяется следующим пушем (12 из 38 запусков). Зависание может уйти игроку зелёным. (P-05)

## Целевая архитектура — суть (`04-target-architecture.md`)
Не переписывать, а закрепить границы: (1) чистое ядро `sim`/`zonemap` + снимки `PdaSnapshot`/`BaseSnapshot`/`PdaModel` как единственный контракт для клиента, с тестом «собрать → разобрать»; (2) один API записи блоков при загрузке чанка и тест, запрещающий обходы; (3) шлюз «мир → симуляция» — игровой код не пишет `ledger`/`cargo` напрямую; (4) единый реестр узлов; (5) менеджеры тика под одним интерфейсом и одним объектом состояния на сервер; (6) `Simulation` делится по месту работ, по одной подсистеме под тест; (7) кодек сохранения со стабильными id — после интерфейсов. Что не делаем: Gradle-модули, DI, JSON-протокол, переписывание `Simulation` разом.
