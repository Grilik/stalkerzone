## Режим первого этапа (обязателен для всех)
- Только исследование, анализ, документы. **Production code не менять.**
- Не удалять, не перемещать, не переименовывать существующие файлы. Массовую переработку документации не делать.
- **Не делать git commit / push / checkout / reset / stash.** Только чтение истории (`git log`, `git show`, `git diff`, `git blame`).
- Писать только в свой файл (таблица выше) внутри этой папки. Чужие файлы не править: нужна правка — сообщение владельцу.
- Старые документы и инструкции могут противоречить друг другу и коду. Старые планы не считаются актуальными автоматически: при расхождении указывать, что новее (дата коммита), и что реально в коде.
- Каждое утверждение — с опорой: `файл:строка`, коммит, PR. Отделять «проверено по коду» от «предположение».
- Временные файлы — в scratchpad сессии, не в корень репозитория.
