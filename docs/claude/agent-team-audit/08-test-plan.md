## 0. Принципы и владельцы
- **Роли проекта.** Программист: `sim`, `world`, CI, сервер. Строитель: сборщики `zonemap/build/*` и чек-листы построек. Конвейер: узкие карточки с красным тестом. Пользователь: плейтест и слияние PR. Штаб: приоритеты и документы. QA: независимая проверка (роль команды аудита, временная).
- **Каноническая среда «зелёного»:** Linux CI (`build.yml`). Локальный Windows считается поддерживаемым только после пунктов 1.1 и 1.2 (сейчас `tools/simtest.ps1` красный: 03, 4.1).
- **Лестница.** Уровень N+1 запускается, только когда уровень N зелёный. Исключение: уровень 4 (плейтест) идёт в параллель по готовому `nightly`.
- **Что считать «зелёным»** задано числом для каждого уровня. Фраза «тесты прошли» без числа не принимается.
- **Метки приоритета:** P0 до следующего плейтеста, P1 до конца текущего этапа «Малого Кордона», P2 позже.

## 6. Правила для карточек конвейера (падающий тест)

Действующие правила (`06-conveyor-v2.md`, `tools/conveyor/rules.txt`) сохраняются: паспорт, красный тест на main, зелёный с правкой, потолок 15 минут и $0,30, тест не менять, файлы только из паспорта, статус ставит конвейер после слияния. Дополнения:

| № | Правило | Основание |
|---|---|---|
| К-1 | В карточку вставляется первая строка вывода красного теста (текст `FAIL …`) на `main`. Это доказывает, что тест красный по нужной причине, а не из-за компиляции или окружения | Защита от «красного не по делу» |
| К-2 | Тест не должен быть тавтологией. Автор карточки отмечает в карточке, какой негативный случай (граница, обратный пример) проверяется. QA или человек просматривает тест до выдачи карточки | Тест и правка написаны одним автором (03, R-11) |
| К-3 | Если результат карточки должен проявиться в мире, в паспорт добавляется поле «**Мир:** серверная проверка / чек-лист / нет». При «нет» статус карточки «готово (ядро)», а не «готово» | 4.8: 056, 059, 061, 064 зелёные, в мире не работают |
| К-4 | Новый публичный метод `sim`, не вызываемый из production, допускается только со ссылкой на карточку-потребитель в паспорте (`Потребитель: NNN`). Карточки-потребители ставятся в план сразу | 061, 064, 051, 052 |
| К-5 | Карточка, меняющая формат сохранения, повышает версию, обновляет `SaveVersionTest` и пишет «новый мир: да или нет» | R-03, C-12 |
| К-6 | Общие тесты (`SiteTest`, `PrefabsTest`, `WorkRolesTest`, `KordonPaceTest` и др.) исполнитель не правит. Автор карточки готовит их заранее на main (как в П-17) | Практика П-17 работает, правило закрепить |
| К-7 | Новый код в `world`, `npc`, `client` не проверять по исходникам, если можно вынести чистое ядро в `sim` или `zonemap`. Тест по исходникам допустим только как временная защита с нормализацией `\r\n` | R-07 |
| К-8 | Любой `Random` в тесте с фиксированным сидом. Тест, упавший при повторе без изменений, получает карточку на исправление (как 042 и 043) | 4.2 |
| К-9 | Метрики конвейера считают «слито без ручных правок» по авторам коммитов ветки (коммит `слить main` автора `Claude` означает ручную правку). Отдельно учитывать число сессий Claude на написание карточки | 03, 4.7: метрика «ok=1» у всех 23 PR при 5 ручных слияниях |
| К-10 | Повторный запуск карточки не перезаписывает более новый тест: `conveyor.sh` сверяет копию `docs/tasks/tests/X` с `src/test/java/X` и останавливается при расхождении. После слияния копия в `docs/tasks/tests` удаляется | R-18 (4 копии уже расходятся) |
| К-11 | Карточки на постройки, облик, интерфейсы и всё без проверяемого теста конвейеру по-прежнему не отдаются | `06-conveyor-v2.md:15` |
