## 3. Безопасность и стабильность: P-03 и P-05

### 3.1 Что именно происходит при зависании
Декор уровня ставится на серверном потоке внутри `ChunkEvent.Load`, когда чанк ещё переводится в «полный». Любой вызов, который через `Level` трогает соседний (или этот же) чанк — `onPlace` рельсов, `onRemove` блока с BlockEntity, `setChanged` у BlockEntity, чтение высоты за ±48 блоков — заставляет серверный поток ждать чанк, который готовится этим же потоком. Три исправления (05–07.11): #64 (тяжёлые сборщики отключены), #67 (декор узла не читает далёкие точки, сторож), #117 (`rawSet` без `onPlace`); первое зависание у игрока — 31.10.

### 3.2 Что защищает сейчас и чего не хватает
| Защита | Есть | Чего не хватает |
|---|---|---|
| `ObjPropBlock.safeSet`/`rawSet`/`placeInChunk` | да: все записи декора и переноса уровня идут через них | `WallBuilder.java:42` обходит `safeSet` для блоков с BlockEntity; ветка воды (`:78-85`) пишет в секцию без карт высот и света; ветка BE внутри `safeSet` идёт через ванильный `setBlockState` |
| `ServerWatchdog` | да: стек в лог при остановке тика > 10 с | не называет систему-виновника по имени (этап 3) |

### 3.3 Фактическая безопасность обходов `safeSet`
- `WallBuilder.java:42` срабатывает только если в столбце периметра стоит блок с BlockEntity (улей, сундук, спавнер). Ульи у деревьев убраны (#63), ванильные структуры в биомах мода не найдены, поэтому вероятность низкая — **но не нулевая и не доказанная**. Стоимость закрытия — одна карточка (Э0-07).
- Ветка воды: пишет в секцию без обновления карт высот и света — зависания не даёт, даёт неверный свет/высоту у воды. Низкий приоритет, в Э0-07 закрыть той же правкой (`rawSet` для жидкостей тоже).
- Ветка BE внутри `safeSet` (`c.setBlockState(pos, s, false)` для состояний с BlockEntity): срабатывает при постановке пропса с BlockEntity при загрузке чанка — FramedBlocks (камуфляж через NBT). `applyNbt` без `setChanged` проверяет `FramedTest`. Оставить, но включить в обобщённый тест как единственное разрешённое место.
