# 06. Конвейер v2 — дешевле и с результатом (штаб, 06.11.2026)

Пользователь 06.11: «нравилась изначальная идея конвейера, но большой расход и плохой результат».

## Почему так (разбор `tools/conveyor/conveyor.sh` и истории карточек)
1. **Не те задачи.** Конвейеру отдавали то, что требует глаз и вкуса: постройки «по обмерам» (карточки 035–040 — АТП, элеватор, свиноферма, мост, блокпост). Дешёвая модель картинку не видит, результат плохой → 01.11 эти сборщики отключили, а те же постройки в чатах с Claude получились (бункер, деревня). Деньги ушли впустую.
2. **«Готово» проверяется тестами кода, а не игрой.** Карточка «зелёная», а в игре не то; ревьюер — тоже дешёвая модель (GLM Flash) и ловит мало. Плюс автослияние зелёных PR → брак попадает в main, его потом чинят чаты.
3. **Нет потолка расхода на карточку.** Исполнитель — до 60 мин (`run agent 3600`) с `--retries 6`, потом старший Claude Sonnet до 20 мин / 80 ходов, потом второй круг ревью и правок. Стоимость не ограничена ничем, кроме порога остатка `MIN_BALANCE`. Неудачная карточка проходит все ступени — самая дорогая.
4. **Карточки большие и размытые**, агент читает много репозитория → длинный контекст на каждом шаге.
5. **Две линии параллельно** мешают друг другу (конфликты, общие файлы) — двойной расход на переделки.

## Что меняем (предложение штаба)
**Принцип: конвейер делает узкую работу по готовому тесту; думает и проверяет — Claude в чатах.**
1. **Карточка для конвейера = падающий тест + короткое задание.** Её пишет «Программист» (Claude): точные файлы, что поменять, и тест, который сейчас красный. Конвейер должен сделать тест зелёным, ничего больше. Пример годных задач: таблица весов патронов TaCZ, перевод `System.out` на логгер по всему коду, данные иконок КПК, таблицы цен, локализация строк, мелкие правки по готовому списку.
2. **Запрещено конвейеру:** постройки и облик, интерфейсы (внешний вид), всё, где «готово» нельзя проверить тестом. Метка в карточке `конвейер: да/нет`; без «да» карточку конвейер не берёт.
3. **Потолок на карточку:** ≤ 15 мин исполнителя, `--retries 2`, бюджет по деньгам (например $0,30 — разница баланса OpenRouter; превысил — стоп). Не справился — **одна** попытка, без старшего Claude; PR помечается «не вышло», карточка возвращается «Программисту» (он либо дробит её, либо делает сам). Старший Claude в конвейере — выключить (`CLAUDE_DAILY_LIMIT=0`): он дорог и тратит общие лимиты.
4. **Узкий контекст:** в задании — список файлов, которые можно читать/менять; `.clineignore` на `docs/`, `tools/xray/`, превью и т. п.
5. **Проверка:** тесты + запуск сервера в CI на синтетическом уровне (`fake_szl.py`, мир создаётся, 20 TPS, сохранение) — открытая проблема 3. Ревью дешёвой моделью оставить как подсказку, **без автослияния**: PR конвейера сливает пользователь после короткого взгляда «Программиста» или штаба.
6. **Одна линия** вместо двух.
7. **Метрики в PR и сводке Telegram:** стоимость карточки, сколько попыток, слито без переделок или нет. Через неделю — итог: цена одной *слитой* карточки. Если больше, чем сделать то же в чате, — конвейер выключаем.
