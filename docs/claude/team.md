# Команда моделей Claude Code

Обновлено 15.11.2026, штаб. Определения ролей — `.claude/agents/*.md` (Claude Code подхватывает их сам после `git pull`). Основа — опыт аудита 12–13.11 (Agent Teams: Fable — руководитель, Opus — ведущий разработчик, Sonnet — инженер и QA).

## Кто есть кто

| Роль | Модель | Когда звать | Что делает | Может править |
|---|---|---|---|---|
| **Ведущий** — основная сессия в консоли | Opus (`claude --model opus`) | всегда | берёт задачу из `docs/roadmap.md`, делит на части, поручает, собирает PR, отчитывается | всё |
| `@builder` — Строитель | Opus, в своём worktree | постройки, их места в мире, места NPC | сборщики, постановка в TheZone, превью | `zonemap/build/*`, `tools/prefab`, `tools/thezone`, `docs/kordon_objects` |
| `@sim-worker` — исполнитель симуляции | Sonnet, в своём worktree | узкая задача `sim/*` с падающим тестом | минимальная правка под тест | `sim/*`, `zonemap/*` (чистая Java) |
| `@reviewer` — проверяющий | Sonnet | после каждой задачи, перед слиянием | проверка по коду, тестам, правилам, конфликтам с main | ничего |
| `@scout` — разведчик | Haiku | найти, где что лежит; выжимка из лога или документа | поиск и чтение | ничего |
| `@architect` — архитектор | **Fable** | редко: архитектура, атлас и координаты, неочевидная ошибка, план этапа | решение с вариантами и задачами | ничего |
| Конвейер (GitHub Actions) | DeepSeek через OpenRouter | узкие карточки симуляции, когда Claude не нужен | ≈ $0,01 за карточку | по паспорту карточки |

## Почему Fable не во главе
Fable — самая сильная модель, но по наблюдению пользователя одна сессия на ней съедает до половины недельного лимита. Ведущий работает весь день, поэтому ведущий — Opus. Fable зовут как консультанта: один вопрос → одно решение → задачи в дорожную карту. Примерно 1–3 раза в неделю: перед этапом, при выборе архитектуры, когда Opus дважды не нашёл причину ошибки.

## Правила экономии лимита
1. Ведущий не читает много файлов сам — отправляет `@scout` (Haiku в разы дешевле) и получает выжимку.
2. Узкая задача симуляции с тестом — сначала конвейер (DeepSeek), если не вышло — `@sim-worker` (Sonnet), ведущий — только если оба не справились.
3. Параллельно пишут код не больше двух агентов, и только в разных worktree и по непересекающимся файлам. Иначе конфликты слияния (как #102, #114, #115).
4. Каждая готовая задача → `@reviewer` → PR. Сливает пользователь.
5. Длинные проверки (сборка Gradle, сервер) — один раз в конце задачи, не после каждой правки.
6. Большие логи и документы — grep/tail, не целиком.
7. Когда лимит близко к концу: `/model sonnet` для ведущего; Fable не звать.
8. Одна задача — один PR, номер задачи в начале заголовка (страница прогресса ставит статус сама).

## Как поручать (для ведущего)
- «@builder Э2-02: деревня новичков на месте TheZone (координаты …)»
- «@sim-worker Э6-02: …, тест `…Test`, файлы `sim/People.java`»
- «@scout найди, где выставляется население узла и какие тесты это проверяют»
- «@reviewer проверь ветку `e2-02-village` против задачи Э2-02»
- «@architect: как пересчитать разметку уровней Anomaly на TheZone — одно преобразование на локацию или по опорным точкам с невязкой? Дай решение и задачи»
