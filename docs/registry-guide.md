# Единый реестр состояния проекта Living Zone

**Файл:** `docs/project-tasks.json`  
**Создан:** 18.11.2026  
**Валидатор:** `tools/registry/validate.py`  
**Утилиты:** `tools/registry/utils.py`

## Назначение

Единый источник истины для всего состояния проекта:
- 132 требования из `requirements.json`
- 180 задач: 171 из `roadmap.md` + 2 плейтеста (ПТ-1/ПТ-2) + 7 К-карт (К1/К15/К16/К5 — ревизия 18.11; К2/К17/К33 — ревизия 19.11)
- Связи между требованиями и задачами
- История выполнения, PR, статусы

Заменяет три независимых источника (requirements.json, roadmap.md, отдельные таблицы Qwen) одним структурированным реестром.

## Структура реестра

```json
{
  "meta": {
    "version": 2,
    "created": "2026-11-18T...",
    "updated": "2026-11-18T...",
    "source_files": [...],
    "migration_note": "..."
  },
  "entities": [
    {
      "id": "R-WLD-01",
      "type": "requirement",
      "title": "Бесшовная карта Зоны...",
      "status": "PLANNED",
      "linked_tasks": ["Э1-09"],
      "updated": "2026-11-18T...",
      ...
    },
    {
      "id": "Э0-01",
      "type": "task",
      "title": "Ворота CI: nightly только после...",
      "status": "TESTS_PASSED",
      "assignee": "Claude Code",
      "linked_requirements": ["R-ARC-04"],
      "pr_number": 118,
      "merged_at": "2026-11-10T...",
      ...
    }
  ]
}
```

## Типы сущностей

- **requirement** — требование из мастер-спецификации
- **task** — задача из roadmap
- **subtask** — подзадача (пока не используется)

## Девять статусов жизненного цикла

1. **PLANNED** — запланировано
2. **IN_PROGRESS** — выполняется
3. **CODE_COMPLETE** — код написан, но проверки не завершены
4. **TESTS_PASSED** — автоматические тесты пройдены
5. **GAME_VERIFIED** — проверено в Minecraft
6. **ACCEPTED** — принято пользователем/штабом
7. **BLOCKED** — заблокировано
8. **DEFERRED** — отложено
9. **REJECTED** — отклонено

**Важно:** `TESTS_PASSED` ≠ `ACCEPTED`. Слитый PR = `TESTS_PASSED`, но принятие требует явного подтверждения после проверки в игре.

**Правило GAME_VERIFIED (D3 аудита 18.11):** статус присваивается только при подтверждённом плейтесте (дата, версия, отчёт). Пройденные автотесты без плейтеста — это `TESTS_PASSED`, не `GAME_VERIFIED`.

## К-карты и состояние слияния

Задачи Qwen (К1, К15, К16, К5…) хранятся как `task` с полем `tests` (список тестовых классов). Технический статус и состояние слияния отражаются раздельно:
- `status` — технический статус (`TESTS_PASSED` после зелёных тестов/CI);
- `pr_number` + `merge_commit` + `merged_at` — факт слияния (у неслитой задачи `merge_commit`/`merged_at` = null, даже если CI зелёный);
- `notes` — подробности и ссылка на коммит ветки.

## Обязательные поля

Для всех сущностей:
- `id` — уникальный идентификатор
- `type` — тип сущности
- `title` — название
- `status` — один из 9 статусов
- `updated` — дата последнего обновления

Для задач дополнительно:
- `assignee` — исполнитель
- `linked_requirements` — список ID связанных требований

Для требований дополнительно:
- `linked_tasks` — список ID связанных задач

## Как обновлять реестр

### Вручную

Редактировать `docs/project-tasks.json` напрямую, затем проверить валидатором:

```bash
python3 tools/registry/validate.py
```

Валидатор проверит (ошибки целостности дают ненулевой exit code):
- Уникальность ID
- Корректность статусов и типов
- Наличие обязательных полей (`id`, `type`, `title`, `status`, `updated`)
- Целостность связей: висячие ссылки и не-списки в `linked_tasks`/`linked_requirements` — ошибки

### Из кода (Python)

```python
from tools.registry.utils import load_registry, get_entity_by_id

# Загрузить реестр
registry = load_registry()

# Найти задачу
task = get_entity_by_id(registry, "Э0-01")

# Обновить статус
task["status"] = "ACCEPTED"
task["updated"] = datetime.now().isoformat()

# Сохранить
with open("docs/project-tasks.json", "w", encoding="utf-8") as f:
    json.dump(registry, f, ensure_ascii=False, indent=2)
```

### Автоматически из GitHub

Скрипт миграции обновляет статусы задач на основе слитых PR:
- Если PR с номером задачи слит → `TESTS_PASSED`
- Явные статусы из roadmap.md (`готово`, `отложено`) преобразуются в `ACCEPTED`, `DEFERRED`
