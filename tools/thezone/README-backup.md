# Резервирование и откат TheZone (Э1-03)

## Быстрый старт

### Создать резерв перед работой
```powershell
cd C:\MineStalker\stalkerzone-git\tools\thezone
.\backup_world.ps1 -Label "перед_Э2-01"
```

### Откатить после ошибки
```powershell
.\restore_world.ps1 -BackupName "2026-11-18_14-30-00_перед_Э2-01"
```

### Список доступных резервов
```powershell
Get-ChildItem C:\MineStalker\backups\thezone-backups\
```

## Структура

- **Оригинал:** `C:\MineStalker\world\golden\` (1.8 ГБ, не трогать)
- **Рабочая копия:** `C:\MineStalker\world/work-fresh\` (правим здесь)
- **Резервы:** `C:\MineStalker\backups\thezone-backups\<метка>\`

## Что создаёт резерв

- `region/` — все регионы мира
- `level.dat` — настройки мира
- `entities/` — сущности (если есть)
- `checksums.md5` — MD5 всех файлов

## Безопасность

✅ Откат **проверяет MD5** перед восстановлением
✅ Откат **сохраняет текущее состояние** перед затиранием
✅ Резерв **проверяется** сразу после создания

## Когда делать резерв

- Перед **любой** правкой мира (Э1-10, Э1-12, Э2-01)
- После **успешной** задачи (для отката к хорошему состоянию)
- Перед **экспериментами** (проверка скриптов)

## Золотая копия TheZone (Э1-11)

Версионируемый эталон `vN` для кнопки **«Зона»** в меню создания мира. Формат — тот же, что у резервов
Э1-03 (`checksums.md5`, MD5 каждого файла), плюс `golden.json` (версия, источник, состав, точка появления).

```powershell
# создать следующую версию из рабочей копии (только чтение; level.dat готовится как в Э1-08,
# точка появления — из атласа world.json)
python -I tools/thezone/golden_copy.py make C:\MineStalker\world/work-fresh <папка игры>\stalkerzone\golden

# целостность версий / список
python -I tools/thezone/golden_copy.py verify <папка игры>\stalkerzone\golden
python -I tools/thezone/golden_copy.py list   <папка игры>\stalkerzone\golden
```

- Каталог по умолчанию в игре: `<папка игры>/stalkerzone/golden` (переопределение: `-Dstalkerzone.golden=…`).
- Номера версий строго возрастают; существующая версия не перезаписывается; сборка идёт во временном
  каталоге и становится эталоном только после сверки MD5 — противоречащих эталонов не бывает.
- Кнопка «Зона» создаёт **независимую копию** старшей целой версии в `saves/` (атомарно, со сверкой;
  при ошибке временный каталог удаляется). Обновления золотой копии созданные миры не затрагивают.
- В новый мир не попадает `data/stalkerzone_sim.dat`: у каждого мира своя история симуляции
  и собственный сохраняемый `simSeed` (Э1-11В, `ZoneData`).
- Оригинал `C:\MineStalker\world\golden` и рабочая копия при создании золотой копии только читаются.
